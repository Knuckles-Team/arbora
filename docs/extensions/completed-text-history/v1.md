# Completed-text conversation history, version 1

Extension URI: `https://knuckles-team.github.io/arbora/extensions/completed-text-history/v1`

This optional A2A 0.3 profile supports continuation from completed user/assistant
turns in a stable, retained native graph. It does not restore interrupted model
or tool execution. The implementation remains experimental until native and
installed restart qualification is complete.

## Discovery and activation

The authenticated `/.well-known/agent-card.json` advertises this exact URI in `capabilities.extensions`.
It uses `required: false` and no required parameters.
Advertisement requires the configured strict adapter and its schema, host-provider and operation bindings. Absence means unsupported. Advertisement is
not proof of storage health, graph enablement, caller access or context readiness.

For each continuation, read the authenticated card, then send the exact URI in
`X-A2A-Extensions` on the existing `POST /a2a` `message/send` request. Use the
existing `message.contextId` and fresh message/idempotency identifiers for the
new turn. Do not send a client-owned transcript as execution authority.

The server must select the strict completed-text contract or refuse before admission/claim.
It must not silently fall back to context grouping. Native
owner, tenant, head, profile and lease checks remain authoritative. Initial
native graph enablement requires the operator grant; this header grants none.

Successful activated responses echo the URI in `X-A2A-Extensions`. The returned
context must equal the requested canonical context. If the echo is absent or
the context differs after sending, the outcome is uncertain: do not automatically
retry. Base A2A permits an old server to ignore unknown extensions.
Card preflight cannot guarantee no effects across a changed or heterogeneous server deployment.

## Refusal and compatibility

Missing native schemas or bindings and unknown profile versions refuse.
Unavailable or foreign contexts and legacy contexts without durable profile history refuse.
Unsafe restoration of the current task refuses. A present current checkpoint never falls back
to completed history. A failed or uncertain terminal commit never authorizes
repeating effects. Completed results are published only after durable commit.

Clients without this extension retain ordinary A2A behavior, which does not by
itself imply durable model history. `stateTransitionHistory` describes task-state
history and is not a substitute for this extension. Future incompatible profile
semantics require a different URI; there is no automatic version fallback.
