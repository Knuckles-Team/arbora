# GRAPHOS-DATA-MARKET requirements

| ID | Requirement | Verification |
|---|---|---|
| `GRAPHOS-DATA-MARKET-R001` | **Durable, deduplicated flip alert delivery.** graph-os subscribes durably to the finance flip event topic and delivers alerts to configured notification channels, deduplicating by tenant, event ID, and subscriber so a restart cannot cause a duplicate user-visible alert. An alert never authorizes an order or changes a portfolio. | Proven by a restart/redelivery test confirming at-least-once transport with idempotent, deduplicated delivery. |
| `GRAPHOS-DATA-MARKET-R002` | **Scheduled finance backfill, scan, and explanation jobs.** graph-os schedules finance backfill, scan, and flip-explanation jobs through its existing scheduler, recording each schedule's tenant, owner, authorized action, timezone, trigger, idempotency key, and last run, so a daylight-saving transition or replay cannot duplicate an effect. The explanation itself is produced by the agent workflow and must cite its exact calculation inputs. | Proven by a scheduler test crossing a daylight-saving transition and a replay test confirming no duplicate job execution. |
| `GRAPHOS-DATA-MARKET-R003` | **Server-side finance and markets reads and paper order submission.** graph-os serves tenant-scoped market and finance reads, and paper order submission, through graph_os/api/ops/finance.py and markets.py, with the market read logic ported server-side into graph_os/finance/markets.py. Each read requires the finance:read grant. If tenant or account binding is unverified, return a typed unavailable result before any provider call. Paper order submission requires a tenant-bound account and the finance:paper-trade grant. | Acceptance: two-tenant tests must confirm zero cross-tenant reads. A negative test must confirm unverified account binding returns unavailable before any provider call. |
| `GRAPHOS-DATA-MARKET-R004` | **One-at-a-time application admission with rollback.** graph-os admits one named application and its data source into the shared data plane at a time, using a dry-run plan, an idempotency key, explicit approval, health and parity probes, and a rollback fence. An application's existing ingest connector is retired only after the admitted source is healthy, parity checks pass, and the retirement is approved. | Proven by a restart/fault test demonstrating a failed admission rolls back without retiring the prior connector. |
| `GRAPHOS-DATA-MARKET-R005` | **schema_context query surface for tables and ontology mappings.** graph-os serves an authenticated schema_context query over REST and MCP that answers a table or object's definition, joins, ontology class mapping, owning application, and change impact, labelling any unverified or inferred relationship as a proposal rather than an approved fact. If the graph engine has no schema-context capability or approved catalog snapshot for the source, graph-os returns a typed unavailable result instead of fabricating an answer. | Proven by contract tests covering each intent (definition, joins, ontology, owner, impact) and a negative test for an unsupported source returning a typed unavailable result. |
| `GRAPHOS-DATA-MARKET-R006` | **Recurring DCA plans with deterministic, non-duplicating proposals.** graph-os stores a recurring dollar-cost-averaging plan's owner, tenant, symbol, account binding, decimal amount and currency, timezone, recurrence rule, bounds, pause state, and paper or live mode, and produces one durable proposal per due occurrence with a key derived from the plan revision so replay or clock drift cannot create a duplicate. Paper mode executes only under the paper grant and lease; live mode stays proposal-only until a human approves the exact preview and a connector consumes a write-back lease through the governed path in AU-CONTEXT-R006. A missed or failed contribution is reported, never silently skipped or doubled. | Proven by a replay and clock-drift test asserting exactly one proposal per occurrence, and a fault test confirming a missed contribution is reported rather than silently dropped. |
| `GRAPHOS-DATA-MARKET-R007` | **Confirmed order and position changes.** Require explicit confirmation before an order or position effect. Consume the SDK-GOVERNED-WRITEBACK-R001.1 through R001.6 signature-verification contract for wallet operations. EG owns authorization; GraphOS serves authenticated confirmation and preserves its decision. Keep wallet operations unavailable until the producer and all durable bindings are implemented. GRAPHOS-DATA-MARKET-R003 owns paper submission; GRAPHOS-OPS-R017.2 owns subject ownership. | Served acceptance in tests/integration/test_order_confirmation.py; runtime proof remains required. |
| `GRAPHOS-DATA-MARKET-R007.1` | **Model.** OrderChange and PositionChange bind exact intent. WalletOperation imports SDK WalletBusinessIntent and WalletExecutionEnvelope. Proof and confirmation metadata remain outside business parameters. The plan defines the exact immutable projection; never embed WalletProofRequest inside hashed intent. Bind authenticated caller tenant and actor, account, network, wallet, operation and exact change-set identity. Read-only models at graph_os/finance/markets.py:34 do not implement this contract. | Served acceptance in tests/integration/test_order_confirmation.py; runtime proof remains required. |
| `GRAPHOS-DATA-MARKET-R007.2` | **Behavior.** Prepare immutable intent and require explicit confirmation under `confirm_before_commit`. `plan_digest` means `params_digest({"intent": WalletBusinessIntent})`. Sign after confirmation; adding proof cannot change that digest. Consume the authenticated SDK proof result unchanged and match every binding before dispatch. A valid signature is insufficient without EG authorization, account entitlement and durable effect reservation. Use the existing effect key for retries; never create another nonce or approval store. | Served acceptance in tests/integration/test_order_confirmation.py; runtime proof remains required. |
| `GRAPHOS-DATA-MARKET-R007.3` | **Wiring.** Register the new operations through graph_os/api/ops/registry_factory.py with Confirm.PLAN. Reuse `_effect` at graph_os/api/invoke/pipeline.py:218 and `bind_plan` at line 230. The operation handler must invoke the admitted connector SDK proof and governed apply composition before any provider effect. The shared WalletExecutionEnvelope extension must separate proof before plan hashing, validation, audit and reservation. HTTP and MCP lack this extension. No order or wallet operation is reachable today. | Served acceptance in tests/integration/test_order_confirmation.py; runtime proof remains required. |
| `GRAPHOS-DATA-MARKET-R007.4` | **Refusal.** Return CONFIRMATION_REQUIRED for absent confirmation and PLAN_MISMATCH for intent tampering. Return POLICY_DENIED for invalid proof and UNAVAILABLE for absent verifier, envelope, trust or durable binding authority. Preserve the SDK typed reason in redacted error details. No refused request reaches provider mutation; an uncertain prior effect enters reconciliation instead of blind retry. | Served acceptance in tests/integration/test_order_confirmation.py; runtime proof remains required. |
| `GRAPHOS-DATA-MARKET-R007.5` | **Evidence.** Record request, tenant, actor, plan and confirmation in the existing audit record. Join EG authorization, proof digest, signer, trust revision and effect receipt. Preserve the SDK verification outcome unchanged. Never log raw signatures, private keys or reusable proof bodies. | Served acceptance in tests/integration/test_order_confirmation.py; runtime proof remains required. |
| `GRAPHOS-DATA-MARKET-R007.6` | **Hot-path proof.** `tests/integration/test_order_confirmation.py::test_wallet_proof_confirmation_and_replay` enters the served operation at POST /api/v1/ops/{op_id} and its MCP twin. Use the real SDK verifier, synthetic keys, durable graph authority and a controlled provider. Serve prepare, confirm, sign and execute; proof insertion preserves the intent digest and yields one effect. Missing confirmation, altered account/network/payload, revoked key, expiry and unavailable producer yield none. Concurrent retries and restart read the same effect receipt without another mutation. | Served acceptance in tests/integration/test_order_confirmation.py; runtime proof remains required. |

| `GRAPHOS-DATA-MARKET-R003.1` | **Market list/search/get.** Define distinct `markets.list`, `markets.search`, and `markets.get` bindings through the shared finance service. List/search are bounded and cursor-paginated; get selects one stable market ID. All require `finance:read` and use the R003.4 projection. | Required acceptance: contract and served tests cover all three bindings, filters, pagination, and get-by-ID without effect calls. |
| `GRAPHOS-DATA-MARKET-R003.2` | **Event list/search/get.** Define distinct `events.list`, `events.search`, and `events.get` bindings through the shared finance service. List/search are bounded and cursor-paginated; get selects one stable event ID. All require `finance:read` and use the R003.4 projection. | Required acceptance: contract and served tests cover all three bindings, filters, pagination, and get-by-ID without effect calls. |
| `GRAPHOS-DATA-MARKET-R003.3` | **Order list/search/get.** Define distinct read-only `orders.list`, `orders.search`, and `orders.get` bindings through the shared finance service, bound to the caller's resolved tenant/account. All require `finance:read` and use the R003.4 projection; order reads are not paper submission. | Required acceptance: served tests cover all three bindings and account scoping with zero mutation calls. |
| `GRAPHOS-DATA-MARKET-R003.4` | **Stable JSON projections.** Inside the existing GRAPHOS-OPS-R010 envelope, list/search return `{schema_version: 1, as_of, items, page: {limit, next_cursor}}`; get returns `{schema_version: 1, as_of, item}`. Use RFC 3339 UTC timestamps, decimal strings, explicit nullable optional fields, deterministic keys, and opaque tenant-bound cursors. Market item: `market_id,event_id,question,status,starts_at,ends_at,outcomes[{name,price}],updated_at`. Event item: `event_id,title,description,status,starts_at,ends_at,market_ids,updated_at`. Order item: `order_id,market_id,side,outcome,price,quantity,status,created_at,updated_at`. Do not expose provider-only extras. | Required acceptance: schema tests pin exact keys/types, nullability, decimal/time encoding, pagination, and REST/MCP normalized JSON. |
| `GRAPHOS-DATA-MARKET-R003.5` | **Authority before provider calls.** For all nine bindings, authorize `finance:read`, resolve the caller tenant and bound account from authenticated authority, then scope the provider request before dispatch. Reject caller-selected tenant/account authority. Missing/mismatched binding returns typed unavailable; scope denial uses R010; inaccessible IDs are nonrevealing. Preserve parent R003 and GRAPHOS-OPS-R017.1. | Required acceptance: served two-tenant cases show refusals make zero provider calls and return no cross-tenant record. |
| `GRAPHOS-DATA-MARKET-R003.6` | **Hosted read/effect separation.** Register the nine reads on the shared REST/MCP service path; read handlers require only `finance:read` and cannot reserve leases or invoke submission. Keep paper submission under parent R003 and its separate `finance:paper-trade`, tenant/account, lease, receipt, and GRAPHOS-OPS-R017.2 ownership requirements. Absent producer or GraphOS capability remains unavailable; this row does not assert implementation. | Required acceptance: served parity and spies prove reads never reach paper submission; existing paper-submit negative/positive acceptance remains required. |
