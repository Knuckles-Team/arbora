# ARBORA-OPS requirements

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-OPS-R001` | **Native MCP/REST facade with A2A unary operations then streaming.** Arbora provides a native MCP and REST host. It fronts the engine and agent-utilities services. It first exposes unary A2A operations: card, send, get, list, and cancel. It then adds durable streaming to those same handlers. | Integration tests exercise the A2A unary endpoints against a fixture engine, followed by a separate test proving durable streaming delivery. |
| `ARBORA-OPS-R002` | **Scoped A2A task routing and fleet tool exposure.** Arbora routes inbound A2A tasks to the correct operation handler and exposes, through its assembled multiplexer, only the caller-authorized subset of fleet tools, including typed work-item retrieval and listing bound by control leases and read classifications. | Integration tests assert inbound A2A tasks resolve to the correct handler and that multiplexer tool listings are filtered per caller. |
| `ARBORA-OPS-R003` | **Remove multiplexer skill/prompt harvest path.** Arbora removes the multiplexer's legacy skill and prompt harvesting and static hydration code path. Arbora sources skills and prompts only through the fleet discovery surface. | A regression test confirms the retired harvest module is absent and unimportable at runtime. |
| `ARBORA-OPS-R004` | **FastMCP 4 bridge for the MCP server.** The Arbora MCP bridge declares and runs on FastMCP 4. It provides native WebMCP support and a single consolidated event loop. Its own probes already exercise this version. | A semantic test suite plus a live probe confirm the deployed bridge reports FastMCP 4. |
| `ARBORA-OPS-R005` | **Stable auth error codes from the engine contract.** Arbora consumes the engine's packaged error-code contract. This includes the stable AUTH_TENANT_MISMATCH, AUTH_AUDIENCE_MISMATCH, and AUTH_POLICY_VERSION_MISMATCH codes. Arbora refuses to start if the installed contract is missing or inconsistent with its generated bindings. | A contract test fails closed when the packaged engine error contract is absent or mismatched against the generated bindings. |
| `ARBORA-OPS-R006` | **Consume the engine's packaged wire-callable contract.** Arbora reads the installed engine package's contract files for methods, errors, scopes, and JSON schemas. It binds operations only for engine methods marked wire-callable in that contract. | A package-contract test confirms the generated registry excludes any method not marked wire-callable in the installed engine contract. |
| `ARBORA-OPS-R007` | **Immutable operation registry with digest and authorization.** Arbora defines one immutable OpSpec registry with typed enums for verb, surface, effect, and scope, producing a canonical form and a stable SHA-256 registry digest, and evaluates per-call authorization at find time. | Unit tests in tests/api/test_registry.py cover canonical-form stability, digest reproducibility, and authorized-evaluation outcomes. |
| `ARBORA-OPS-R008` | **RETIRED: superseded by ARBORA-FLEET-R012.** `ARBORA-FLEET-R012` owns the generated engine-bound operations and their exclusions. | Not applicable. The bound evidence is on `ARBORA-FLEET-R012`. |
| `ARBORA-OPS-R009` | **Single invoke pipeline for authority, effect, and audit.** Arbora funnels every MCP, HTTP, A2A, and fleet call through one invoke pipeline that enforces surface, principal rule, exact scopes, policy, and subject-read checks in order, executes service-bound operations through a dedicated executor, gates destructive effects behind a single-use plan reference bound to the operation and policy revision, and requires console step-up with fresh authentication before admin or human-approval effects complete. | Integration tests exercise allow, deny, plan-expiry, and step-up paths through the invoke pipeline. |
| `ARBORA-OPS-R010` | **Closed error enum and one response envelope.** Arbora defines a closed error-code enum, including UNAUTHENTICATED, UNKNOWN_OP, SCOPE_REQUIRED, and POLICY_DENIED, with a generated engine-error mapping. It converts every surface's response through one shared to_envelope function. | Unit tests check envelope shape and error-code mapping, and a generator diff check compares output against the packaged engine contract. |
| `ARBORA-OPS-R011` | **Six resident MCP verbs with typed discovery.** Arbora implements the six resident MCP verbs (find, ask, why, write, act, manage) through a shared verb constructor with typed input schemas, exposes registry entries as arbora:// resources, and includes the registry digest in the server's published instructions. | Unit tests in tests/api/test_mcp_verbs.py cover verb schema validation, resource listing, and digest presence. |
| `ARBORA-OPS-R012` | **Bounded resolver for natural-language operation lookup.** Arbora resolves natural-language and partial queries to registry operations using combined lexical and semantic ranking over generated descriptors, a tenant- and policy-partitioned outcome moving average, and a bounded result cache, falling any unmatched ask call back to a read-only natural-language query preview rather than a direct mutation. | Unit tests in tests/api/test_resolve.py cover ranking order, cache bounds, and the preview-only fallback behavior. |
| `ARBORA-OPS-R013` | **Generated HTTP API for every registry operation.** Arbora exposes each registry operation at POST /api/v1/ops/{op_id}. It also exposes generated resource routes on a dedicated sub-application. The sub-application has an authentication dependency and CSRF protection for cookie sessions. It also has cursor pagination, idempotency-key handling, and discovery endpoints for the registry and OpenAPI document. | Integration tests in tests/api/test_http_*.py cover routing, authentication, CSRF enforcement, and pagination and idempotency behavior. |
| `ARBORA-OPS-R014` | **Identity self-service and admin operations.** Arbora exposes identity operations. They also cover identity-provider configuration with dry-run, policy and mode transitions, issuer rotation, audit export and verification, and SCIM client management. | `ARBORA-OPS-R015` | **Access elevation, approval, and lease operations.** Arbora exposes access operations for elevation requests, approval and denial, lease listing, authorization checks, and policy explanation.
