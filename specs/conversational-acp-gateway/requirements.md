# GRAPHOS-ACP requirements

| ID | Requirement | Verification |
|---|---|---|
| `GRAPHOS-ACP-R001` | **Conversational ACP gateway session admission and policy.** GraphOS admits an ACP session only for a verified principal from the existing identity path, binds the session immutably to that principal/tenant/scope snapshot, enforces configured idle and absolute expiry limits, and returns one typed `chat_adapter_unavailable` refusal for admission and messages whenever the agent-utilities chat adapter is absent or unreachable, without a local reply or REST fallback. Split into `GRAPHOS-ACP-R001.1` (the graph-os-owned typed session-policy model and admission/refusal check) with the transport wiring to the real ACP endpoint and the identical REST-path projection check remaining open under the parent until `GRAPHOS-ACP-R001.2`'s dependency is satisfied. | Unit and integration tests cover admission refusal for missing/invalid credentials, immutable binding, idle-expired refusal, absolute-expired refusal, the typed adapter-unavailable refusal on both admission and message, identical principal/tenant/scope projection against the REST path, and a status/doctor read that reports adapter and limit state without secrets. |
| `GRAPHOS-ACP-R001.1` | **Typed ACP session-policy model and fail-closed admission check.** graph-os defines the typed `PrincipalContext`/`AcpSessionPolicy`/`AcpSessionSnapshot` model and an `AcpSessionAdmission` that admits only a verified principal, binds the session immutably, enforces idle/absolute expiry, and refuses with a distinct `chat_adapter_unavailable` reason — on both admission and message — whenever the caller-supplied chat-adapter probe reports unavailable, with no transport wired yet. | Proven by unit tests asserting unauthenticated refusal, immutable principal binding, idle- and absolute-expiry refusal, and the dedicated `chat_adapter_unavailable` refusal on both admission and message. |
| `GRAPHOS-ACP-R001.2` | **RETIRED: tracked by agent-utilities AU-CONTROL-001.** Owner dependency: agent-utilities chat adapter. `GRAPHOS-ACP-R001`'s transport wiring and end-to-end session flow depend on agent-utilities exposing a reachable chat-adapter contract, owned by `AU-CONTROL-001` (agent-control-plane). This child tracks that external dependency and stays open — no graph-os transport code is delivered against it — until agent-utilities delivers the adapter contract graph-os's admission check can probe. | Closes by reference to `AU-CONTROL-001` evidence of a reachable chat-adapter contract; no graph-os-side test is bound to this child. |
| `GRAPHOS-ACP-R001.3` | **Model.** Graph OS defines `CodingSessionRequest` (workspace root, declared client capabilities), `WorkspaceGrant` (root, capability, standing flag) and `CodingSessionAdmitted` as frozen types. They live in new `graph_os/acp/coding_session.py`, beside `AcpSessionSnapshot` at `graph_os/acp/session_policy.py:68`. The snapshot gains no mutable field. Client capabilities use the ACP names: `fs/read_text_file`, `fs/write_text_file`, `terminal/create`, `terminal/output`, `terminal/wait_for_exit`, `terminal/kill`, `session/request_permission`. | `tests/acp/test_coding_session.py` asserts the types are frozen, reject an empty root, and reject an undeclared capability name. |
| `GRAPHOS-ACP-R001.4` | **Behavior.** `CodingSessionAdmission.admit` extends `AcpSessionAdmission.admit` (`graph_os/acp/session_policy.py:101`). That function lacks any workspace-root or capability input. Named defaults: `trusted_root_rule` admits a root only when it matches a configured trusted-root entry. `permission_rule` requires `session/request_permission` for `fs/write_text_file` and every `terminal/*` request. A matching standing grant skips that request. Reads pass. Graph OS records each grant on the session. | `tests/acp/test_coding_session_behavior.py` asserts a trusted root is admitted, a read passes, a write needs permission, and a standing grant skips the prompt. |
| `GRAPHOS-ACP-R001.5` | **Wiring.** The existing implementation is `AcpSessionAdmission` at `graph_os/acp/session_policy.py:89`. No production caller reaches it today, since only `tests/acp/test_session_policy.py` constructs it. This child creates the call site: a new `register_acp_routes(app, prefix)` in `graph_os/acp/routes.py` handles the `session/new` wire method. `graph_os/gateway/graph_api.py:368` registers it beside `register_dashboard_routes`, and `graph_os/webui_host/webui_co_service.py:77` calls that function. The route resolves the principal through the existing identity path. It forwards each client-capability request over the same connection to the client. | `tests/acp/test_acp_routes_wiring.py` asserts the app exposes the ACP route after `register_graph_routes` and that `session/new` calls `CodingSessionAdmission.admit`. |
| `GRAPHOS-ACP-R001.6` | **Refusal.** `CodingSessionAdmission` refuses with typed reasons added to `AcpRefusalReason` (`graph_os/acp/session_policy.py:21`). `untrusted_root` applies at `session/new`. `capability_not_declared` applies to a request outside the declared set. `permission_denied` applies when the client rejects `session/request_permission`. `client_disconnected` applies when no client is connected. Each refusal returns before any forwarded request. | `tests/acp/test_coding_session_refusal.py` asserts each reason arrives as the typed refusal, with no forwarded request. |
| `GRAPHOS-ACP-R001.7` | **Evidence.** Each admission and each forwarded capability request emits one trace record. Fields: session ID, principal ID, tenant, workspace root, capability name, permission outcome (`standing`, `granted`, `denied`) and refusal reason. The record carries no file content and no command output. It uses the existing emitter in `graph_os/observability`. | `tests/acp/test_coding_session_evidence.py` asserts the record fields for an admit, a granted write and a denied command, and the absence of file content. |
| `GRAPHOS-ACP-R001.8` | **Hot-path proof.** The entry point is the ACP wire method `session/new` served by `graph_os/acp/routes.py`. The test `tests/acp/test_coding_session_hot_path.py` opens a session with a temporary trusted root. The agent then requests `fs/read_text_file` and `fs/write_text_file`. The read passes and the write waits for `session/request_permission`. An untrusted root is refused at `session/new` with `untrusted_root`. | `tests/acp/test_coding_session_hot_path.py` runs against a fake connected client and the registered route, and asserts the three observations. |
