# ARBORA-ACP requirements

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-ACP-R001` | **Conversational ACP gateway session admission and policy.** Arbora admits an ACP session only for a verified principal from the existing identity path, binds the session immutably to that principal/tenant/scope snapshot, enforces configured idle and absolute expiry limits, and returns one typed `chat_adapter_unavailable` refusal for admission and messages whenever the agent-utilities chat adapter is absent or unreachable, without a local reply or REST fallback. Split into `ARBORA-ACP-R001.1` (the arbora-owned typed session-policy model and admission/refusal check) with the transport wiring to the real ACP endpoint and the identical REST-path projection check remaining open under the parent until `ARBORA-ACP-R001.2`'s dependency is satisfied. | Unit and integration tests cover admission refusal for missing/invalid credentials, immutable binding, idle-expired refusal, absolute-expired refusal, the typed adapter-unavailable refusal on both admission and message, identical principal/tenant/scope projection against the REST path, and a status/doctor read that reports adapter and limit state without secrets. |
| `ARBORA-ACP-R001.1` | **Typed ACP session-policy model and fail-closed admission check.** arbora defines the typed `PrincipalContext`/`AcpSessionPolicy`/`AcpSessionSnapshot` model. It also defines an `AcpSessionAdmission`, which admits only a verified principal and binds the session immutably. It enforces idle and absolute expiry. When the caller-supplied chat-adapter probe reports unavailable, it refuses admission and messages with a distinct `chat_adapter_unavailable` reason. No transport is wired yet. | Unit tests prove unauthenticated refusal, immutable principal binding, and idle- and absolute-expiry refusal. They also prove the `chat_adapter_unavailable` refusal on admission and on messages. |
| `ARBORA-ACP-R001.2` | **RETIRED: tracked by agent-utilities AU-CONTROL-001.** Owner dependency: agent-utilities chat adapter. `ARBORA-ACP-R001`'s transport wiring and end-to-end session flow depend on agent-utilities exposing a reachable chat-adapter contract, owned by `AU-CONTROL-001` (agent-control-plane). This child tracks that external dependency and stays open — no arbora transport code is delivered against it — until agent-utilities delivers the adapter contract arbora's admission check can probe. | Closes by reference to `AU-CONTROL-001` evidence of a reachable chat-adapter contract; no arbora-side test is bound to this child. |
| `ARBORA-ACP-R001.3` | **Model.** Arbora defines `CodingSessionRequest` (workspace root, declared client capabilities), `WorkspaceGrant` (root, capability, standing flag) and `CodingSessionAdmitted` as frozen types. They live in new `arbora/acp/coding_session.py`, beside `AcpSessionSnapshot` at `arbora/acp/session_policy.py:68`. The snapshot gains no mutable field. Client capabilities use the ACP names: `fs/read_text_file`, `fs/write_text_file`, `terminal/create`, `terminal/output`, `terminal/wait_for_exit`, `terminal/kill`, `session/request_permission`. | `tests/acp/test_coding_session.py` asserts the types are frozen, reject an empty root, and reject an undeclared capability name. |
| `ARBORA-ACP-R001.4` | **Behavior: workspace trust and permission rules for coding sessions.** Subsystem: ACP coding sessions. Caller: `session/new` and each client-capability request → `arbora/acp/adapter.py::HostedACPAgent` → `arbora/acp/coding_session.py::CodingSessionAdmission`. `admit` already refuses a root outside the trusted set with `UNTRUSTED_ROOT`. This row adds `CodingSessionAdmission.decide_effect(session, method, *, client_connected, chat_adapter_available, now) -> EffectDecision`. Rule `permission_rule`: `fs/read_text_file` passes. `fs/write_text_file` and every `terminal/*` method need one `session/request_permission` answer. A standing `WorkspaceGrant` for the same root and method skips it. The client answers `allow_once`, `allow_always` or `reject`. The first gives outcome `granted`. The second gives `granted` and adds a standing grant. The third gives `denied`. A standing grant gives outcome `standing`. Trusted roots come from config key `ACP_TRUSTED_ROOTS` in `~/.config/arbora/config.json`: a list of absolute paths, default empty, which admits nothing. A root matches only by exact string equality. Grants live on the in-memory session only and end with it. Refusals: see `ARBORA-ACP-R001.6`. Depends on: `ARBORA-ACP-R001.1`. | Test: `tests/acp/test_coding_session_behavior.py::test_trusted_root_read_write_and_standing_grant` (L2) asserts admission and a passing read. It asserts that a write needs permission and a standing grant skips the prompt. |
| `ARBORA-ACP-R001.5` | **Wiring: the effect path reaches the session policy.** Subsystem: ACP coding sessions. Caller: `POST {prefix}/acp/connections` → `arbora/acp/http_transport.py::register_acp_routes` (registered by `arbora/gateway/graph_api.py`) → `HostedACPAgent.new_session` → `CodingSessionAdmission.admit`. `new_session` is wired today. This row wires the effect path. `_ReadTransport.call` in `arbora/acp/adapter.py` handles reads. A new `_EffectTransport.call` in the same file handles `fs/write_text_file` and `terminal/*`. It calls `decide_effect` and sends `session/request_permission` to the client when the decision needs one. It forwards the request over the same connection only after a `granted` or `standing` outcome. The transport registers with `iterate_client_run` through the run plan's client tools. The host passes `ACP_TRUSTED_ROOTS` to `HostedInvocation.configure_acp` (`arbora/mcp_server/hosted_invocation.py`). Depends on: `ARBORA-ACP-R001.4`. | Test: `tests/acp/test_acp_routes_wiring.py::test_effect_path_reaches_decide_effect` (L3) opens a session through the registered route and asserts `decide_effect` ran for a write. |
| `ARBORA-ACP-R001.6` | **Refusal: typed reasons return before any forwarded request.** Subsystem: ACP coding sessions. Code: `AcpRefusalReason` in `arbora/acp/session_policy.py`. Existing values `UNTRUSTED_ROOT`, `CAPABILITY_NOT_DECLARED`, `CLIENT_DISCONNECTED` and `PERMISSION_REQUIRED` stay. This row adds `PERMISSION_DENIED`. `UNTRUSTED_ROOT` applies at `session/new`. `CAPABILITY_NOT_DECLARED` applies to a method outside the client's declared set. `PERMISSION_DENIED` applies when the client answers `reject` or cancels. `CLIENT_DISCONNECTED` applies when no client is connected. Each reason returns as the ACP error code -32001 with `data.reason` before any forwarded request. Depends on: `ARBORA-ACP-R001.4`. | Test: `tests/acp/test_coding_session_refusal.py::test_each_reason_is_typed_and_forwards_nothing` (L2) asserts each reason and zero forwarded requests. |
| `ARBORA-ACP-R001.7` | **Evidence: one trace record per admission and capability request.** Subsystem: ACP coding sessions. Caller: `HostedACPAgent.new_session` and `_EffectTransport.call` → `arbora/acp/trace.py::emit_acp_record` (new) → the logger `arbora.observability.acp`. Fields: `session_id`, `principal_id`, `tenant`, `workspace_root`, `capability`, `permission_outcome` (`standing`, `granted`, `denied`) and `refusal_reason`. The record carries no file content and no command output. The logger uses the standard OpenTelemetry exporter configured by `arbora/observability/telemetry.py::configure_standard_otel`. Depends on: `ARBORA-ACP-R001.5`. | Test: `tests/acp/test_coding_session_evidence.py::test_record_fields_without_content` (L2) asserts the fields for an admit, a granted write and a denied command. |
| `ARBORA-ACP-R001.8` | **Hot-path proof: coding session over the registered route.** Subsystem: ACP coding sessions. Entry point: ACP method `session/new` on `POST /api/acp/connections`. The test opens a session with a trusted temporary root against a fake connected client. The agent requests `fs/read_text_file` and `fs/write_text_file`. The read passes and the write waits for `session/request_permission`. An untrusted root refuses at `session/new` with `untrusted_root`. Depends on: `ARBORA-ACP-R001.5`, `ARBORA-ACP-R001.7`. | Test: `tests/acp/test_coding_session_hot_path.py::test_read_passes_write_waits_untrusted_root_refused` (L3) runs through the registered route with tenant context and a foreign-principal refusal. |
| `ARBORA-ACP-R001.9` | **Serve bounded read and preview duplex sessions.** Register the authenticated JSON-RPC/SSE route in the shared gateway. Bind each transient connection to the existing verified caller and coding admission snapshot. Correlate bounded client responses, order events, cancel on disconnect, and refuse cross-caller reuse and replay. The local read/preview profile drives AU's received plan with client tools only. The central child retains native planning and server tools. Forward reads; preview writes and commands but return permission_required before any effect request. | Real isolated HTTP/SSE client tests read a temporary file, receive a diff and command preview in order, and prove no write or command dispatch. Missing authority, wrong caller, undeclared reads, stale or duplicate responses, disconnect and queue limits refuse. Durable approvals and effect execution remain owned by the original parent rows. |
| `ARBORA-ACP-R001.9.1` | **Project admitted AU runs through the ACP SDK.** Reuse the received RunRequest and AU native streaming observer, session policy and Pydantic coding presenter. Provide an explicitly composed stdio server without a second agent loop or history store. Bound transient sessions, prompts and all outgoing updates. Revalidate the caller after awaited admission. Resolve client paths lexically to absolute workspace paths; the client still owns filesystem containment. Permit declared reads and non-executing effect previews only. Owner cancellation and teardown remain possible after expiry. | Real SDK subprocess tests initialize, open sessions, stream text, read a temporary client file, cancel active model and read waits, and refuse path escapes, unsupported effects/recovery, identity changes and bounds. Scripted models and synthetic host authority are explicit. Installed-wheel, remote-auth and durable-history acceptance are separate. |
| `ARBORA-ACP-R001.9.2` | **Mount the authenticated experimental HTTP/SSE profile.** Register the shared ACP projection through the gateway's existing identity path. Bind every message to the original verified principal, tenant and scopes; never accept identity or credentials from a query string or JSON-RPC body. Bound frames, connections, queues and response correlation. Refuse duplicate IDs, stale responses and SSE replay. Cancel active AU work on disconnect. | Real HTTP/SSE tests use the SDK codec and temporary client workspace. Prove unauthorized and cross-caller refusal, ordered streaming, bounded backpressure, duplicate/stale response refusal and disconnect cancellation. This custom profile is not standardized Streamable HTTP or durable replay. |
| `ARBORA-ACP-R001.9.3` | **Governed central final answer.** An opt-in factory uses the existing authenticated `agents.run` operation, native task plan and server tools. Bind the actual admitted task/run receipt; publish only its committed final answer. Refuse continuation and nonterminal outcomes. Confirm cancellation through the task owner and readback, otherwise report uncertainty. Bearer renewal supplies the current caller only with unchanged verified authorization and verifier configuration. | Real SDK/HTTP tests cover final answer, private-event exclusion, nonterminal refusal, cancellation before and after admission, uncertain settlement and renewed credentials. Controlled model and owner ports are not live storage or installed-wheel proof. |
