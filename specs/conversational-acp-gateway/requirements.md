# ARBORA-ACP requirements

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-ACP-R001` | **Conversational ACP gateway session admission and policy.** Arbora admits an ACP session only for a verified principal from the existing identity path, binds the session immutably to that principal/tenant/scope snapshot, enforces configured idle and absolute expiry limits, and returns one typed `chat_adapter_unavailable` refusal for admission and messages whenever the meristem chat adapter is absent or unreachable, without a local reply or REST fallback. Split into `ARBORA-ACP-R001.1` (the arbora-owned typed session-policy model and admission/refusal check) with the transport wiring to the real ACP endpoint and the identical REST-path projection check remaining open under the parent until `ARBORA-ACP-R001.2`'s dependency is satisfied. | Unit and integration tests cover admission refusal for missing/invalid credentials, immutable binding, idle-expired refusal, absolute-expired refusal, the typed adapter-unavailable refusal on both admission and message, identical principal/tenant/scope projection against the REST path, and a status/doctor read that reports adapter and limit state without secrets. |
| `ARBORA-ACP-R001.1` | **Typed ACP session-policy model and fail-closed admission check.** arbora defines the typed `PrincipalContext`/`AcpSessionPolicy`/`AcpSessionSnapshot` model. It also defines an `AcpSessionAdmission`, which admits only a verified principal and binds the session immutably. It enforces idle and absolute expiry. When the caller-supplied chat-adapter probe reports unavailable, it refuses admission and messages with a distinct `chat_adapter_unavailable` reason. No transport is wired yet. Caller chain: an ACP request → `HostedACPAgent.new_session` (`arbora/acp/adapter.py:185`) → `AcpSessionAdmission.admit` (`arbora/acp/session_policy.py:107`) and `check_message` (line 126). Shape: `PrincipalContext` (line 44), `AcpSessionPolicy` (line 62), `AcpSessionSnapshot` (line 74), `AcpSessionAdmission` (line 95) and `AcpRefusalReason` (line 21) in `arbora/acp/session_policy.py`; the chat-adapter probe is a caller-supplied boolean `chat_adapter_available`. | Unit tests prove unauthenticated refusal, immutable principal binding, and idle- and absolute-expiry refusal. They also prove the `chat_adapter_unavailable` refusal on admission and on messages. Test: `tests/acp/test_session_policy.py::test_admit_refuses_without_principal`, `tests/acp/test_session_policy.py::test_binding_is_immutable_across_sessions`, `tests/acp/test_session_policy.py::test_check_message_refuses_when_idle_limit_exceeded`, `tests/acp/test_session_policy.py::test_check_message_refuses_when_absolute_limit_exceeded_despite_activity` and `tests/acp/test_session_policy.py::test_admit_refuses_when_chat_adapter_unavailable`. |
| `ARBORA-ACP-R001.2` | **RETIRED: tracked by meristem MERISTEM-RUN-R001.** Owner dependency: meristem chat adapter. `ARBORA-ACP-R001`'s transport wiring and end-to-end session flow depend on meristem exposing a reachable chat-adapter contract, owned by `MERISTEM-RUN-R001` (agent-control-plane). This child tracks that external dependency and stays open — no arbora transport code is delivered against it — until meristem delivers the adapter contract arbora's admission check can probe. | Closes by reference to `MERISTEM-RUN-R001` evidence of a reachable chat-adapter contract; no arbora-side test is bound to this child. |

Shape: frozen dataclasses `CodingSessionRequest` (line 35), `WorkspaceGrant` (line 51) and `CodingSessionAdmitted` (line 66) and the enum `ClientCapability` (line 17) in `arbora/acp/coding_session.py`, built on `AcpSessionSnapshot` of `arbora/acp/session_policy.py`. | `tests/acp/test_coding_session.py` asserts the types are frozen, reject an empty root, and reject an undeclared capability name. | `ARBORA-ACP-R001.4` | **Behavior: workspace trust and permission rules for coding sessions.** Subsystem: ACP coding sessions. Caller: `session/new` and each client-capability request → `arbora/acp/adapter.py::HostedACPAgent` → `arbora/acp/coding_session.py::CodingSessionAdmission`. `admit` already refuses a root outside the trusted set with `UNTRUSTED_ROOT`. This row adds `CodingSessionAdmission.decide_effect(session, method, *, client_connected, chat_adapter_available, now) -> EffectDecision`. Rule `permission_rule`: `fs/read_text_file` passes. `fs/write_text_file` and every `terminal/*` method need one `session/request_permission` answer. A standing `WorkspaceGrant` for the same root and method skips it. The client answers `allow_once`, `allow_always` or `reject`. The first gives outcome `granted`. The second gives `granted` and adds a standing grant. The third gives `denied`. A standing grant gives outcome `standing`. Trusted roots come from config key `ACP_TRUSTED_ROOTS` in `~/.config/arbora/config.json`: a list of absolute paths, default empty, which admits nothing. A root matches only by exact string equality. Grants live on the in-memory session only and end with it. Refusals: see `ARBORA-ACP-R001.6`. Depends on: `ARBORA-ACP-R001.1`. Caller chain: `session/new` and each client-capability request → `HostedACPAgent` (`arbora/acp/adapter.py:86`) → `CodingSessionAdmission.decide_effect` (new method beside `admit` and `check_capability` at `arbora/acp/coding_session.py:85` and `:100`). Shape: add `EffectDecision` (frozen dataclass: `outcome`, `refusal_reason`) and `decide_effect` to `arbora/acp/coding_session.py`; reuse `WorkspaceGrant` for the standing grant and `AcpRefusal` of `arbora/acp/session_policy.py`; the trusted roots reach it through `HostedInvocation.configure_acp(trusted_roots=...)` (`arbora/mcp_server/hosted_invocation.py:50`). | Test (planned): `tests/acp/test_coding_session_behavior.py::test_trusted_root_read_write_and_standing_grant` (L2) asserts admission and a passing read. It asserts that a write needs permission and a standing grant skips the prompt. |
| `ARBORA-ACP-R001.5` | **Wiring: the effect path reaches the session policy.** Subsystem: ACP coding sessions. Caller: `POST {prefix}/acp/connections` → `arbora/acp/http_transport.py::register_acp_routes` (registered by `arbora/gateway/graph_api.py`) → `HostedACPAgent.new_session` → `CodingSessionAdmission.admit`. `new_session` is wired today. This row wires the effect path. `_ReadTransport.call` in `arbora/acp/adapter.py` handles reads. A new `_EffectTransport.call` in the same file handles `fs/write_text_file` and `terminal/*`. It calls `decide_effect` and sends `session/request_permission` to the client when the decision needs one. It forwards the request over the same connection only after a `granted` or `standing` outcome. The transport registers with `iterate_client_run` through the run plan's client tools. The host passes `ACP_TRUSTED_ROOTS` to `HostedInvocation.configure_acp` (`arbora/mcp_server/hosted_invocation.py`). Depends on: `ARBORA-ACP-R001.4`. Caller chain: `POST {prefix}/acp/connections` → `register_acp_routes` (`arbora/acp/http_transport.py:454`, called at `arbora/gateway/graph_api.py:323`) → `_Gateway.endpoint` (line 424) → `HostedACPAgent.new_session` (`arbora/acp/adapter.py:185`) → `CodingSessionAdmission.admit`; the effect path continues → `_EffectTransport.call` (new) → `decide_effect`. Shape: add class `_EffectTransport` beside `_ReadTransport` (`arbora/acp/adapter.py:393`) with the same `call(method, params)` signature; it sends `session/request_permission` through the connected `acp.Client` held by `HostedACPAgent.on_connect` (line 147) and registers with `iterate_client_run` as a client tool. | Test: `tests/acp/test_acp_routes_wiring.py::test_effect_path_reaches_decide_effect` (L3) opens a session through the registered route and asserts `decide_effect` ran for a write. |
| `ARBORA-ACP-R001.6` | **Refusal: typed reasons return before any forwarded request.** Subsystem: ACP coding sessions. Code: `AcpRefusalReason` in `arbora/acp/session_policy.py`. Existing values `UNTRUSTED_ROOT`, `CAPABILITY_NOT_DECLARED`, `CLIENT_DISCONNECTED` and `PERMISSION_REQUIRED` stay. This row adds `PERMISSION_DENIED`. `UNTRUSTED_ROOT` applies at `session/new`. `CAPABILITY_NOT_DECLARED` applies to a method outside the client's declared set. `PERMISSION_DENIED` applies when the client answers `reject` or cancels. `CLIENT_DISCONNECTED` applies when no client is connected. Each reason returns as the ACP error code -32001 with `data.reason` before any forwarded request. Depends on: `ARBORA-ACP-R001.4`. Caller chain: a client request on an open session → `_EffectTransport.call` (new, `arbora/acp/adapter.py`) or `HostedACPAgent.new_session` (line 185) → `CodingSessionAdmission.decide_effect` or `admit` → `AcpRefusal` (`arbora/acp/session_policy.py:35`) → the ACP error response. Shape: add the member `PERMISSION_DENIED = "permission_denied"` to `AcpRefusalReason` (line 21); map every member to ACP error code -32001 with `data.reason` in one helper in `arbora/acp/adapter.py`; reuse `AcpRefusal` as the only exception. | Test: `tests/acp/test_coding_session_refusal.py::test_each_reason_is_typed_and_forwards_nothing` (L2) asserts each reason and zero forwarded requests. |
