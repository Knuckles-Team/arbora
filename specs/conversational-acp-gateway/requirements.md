# ARBORA-ACP requirements

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-ACP-R001` | **Conversational ACP gateway session admission and policy.** Arbora admits an ACP session only for a verified principal from the existing identity path, binds the session immutably to that principal/tenant/scope snapshot, enforces configured idle and absolute expiry limits, and returns one typed `chat_adapter_unavailable` refusal for admission and messages whenever the meristem chat adapter is absent or unreachable, without a local reply or REST fallback. Split into `ARBORA-ACP-R001.1` (the arbora-owned typed session-policy model and admission/refusal check) with the transport wiring to the real ACP endpoint and the identical REST-path projection check remaining open under the parent until `ARBORA-ACP-R001.2`'s dependency is satisfied. | Unit and integration tests cover admission refusal for missing/invalid credentials, immutable binding, idle-expired refusal, absolute-expired refusal, the typed adapter-unavailable refusal on both admission and message, identical principal/tenant/scope projection against the REST path, and a status/doctor read that reports adapter and limit state without secrets. |
| `ARBORA-ACP-R001.1` | **Typed ACP session-policy model and fail-closed admission check.** arbora defines the typed `PrincipalContext`/`AcpSessionPolicy`/`AcpSessionSnapshot` model. It also defines an `AcpSessionAdmission`, which admits only a verified principal and binds the session immutably. It enforces idle and absolute expiry. When the caller-supplied chat-adapter probe reports unavailable, it refuses admission and messages with a distinct `chat_adapter_unavailable` reason. No transport is wired yet. | Unit tests prove unauthenticated refusal, immutable principal binding, and idle- and absolute-expiry refusal. They also prove the `chat_adapter_unavailable` refusal on admission and on messages. |
| `ARBORA-ACP-R001.2` | **RETIRED: tracked by meristem AU-CONTROL-001.** Owner dependency: meristem chat adapter. `ARBORA-ACP-R001`'s transport wiring and end-to-end session flow depend on meristem exposing a reachable chat-adapter contract, owned by `AU-CONTROL-001` (agent-control-plane). This child tracks that external dependency and stays open — no arbora transport code is delivered against it — until meristem delivers the adapter contract arbora's admission check can probe. | Closes by reference to `AU-CONTROL-001` evidence of a reachable chat-adapter contract; no arbora-side test is bound to this child. |
| `ARBORA-ACP-R001.3` | **Model.** Arbora defines `CodingSessionRequest` (workspace root, declared client capabilities), `WorkspaceGrant` (root, capability, standing flag) and `CodingSessionAdmitted` as frozen types. They live in new `arbora/acp/coding_session.py`, beside `AcpSessionSnapshot` at `arbora/acp/session_policy.py:68`. The snapshot gains no mutable field. Client capabilities use the ACP names: `fs/read_text_file`, `fs/write_text_file`, `terminal/create`, `terminal/output`, `terminal/wait_for_exit`, `terminal/kill`, `session/request_permission`. | `tests/acp/test_coding_session.py` asserts the types are frozen, reject an empty root, and reject an undeclared capability name. |
| `ARBORA-ACP-R001.4` | **Behavior.** `CodingSessionAdmission.admit` extends `AcpSessionAdmission.admit` (`arbora/acp/session_policy.py:101`). That function lacks any workspace-root or capability input. Named defaults: `trusted_root_rule` admits a root only when it matches a configured trusted-root entry. `permission_rule` requires `session/request_permission` for `fs/write_text_file` and every `terminal/*` request. A matching standing grant skips that request. Reads pass. Arbora records each grant on the session. | `tests/acp/test_coding_session_behavior.py` asserts a trusted root is admitted, a read passes, a write needs permission, and a standing grant skips the prompt. |
| `ARBORA-ACP-R001.5` | **Wiring.** The existing implementation is `AcpSessionAdmission` at `arbora/acp/session_policy.py:89`. No production caller reaches it today, since only `tests/acp/test_session_policy.py` constructs it. This child creates the call site: a new `register_acp_routes(app, prefix)` in `arbora/acp/routes.py` handles the `session/new` wire method. `arbora/gateway/graph_api.py:368` registers it beside `register_dashboard_routes`, and `arbora/webui_host/webui_co_service.py:77` calls that function. The route resolves the principal through the existing identity path. It forwards each client-capability request over the same connection to the client. | `tests/acp/test_acp_routes_wiring.py` asserts the app exposes the ACP route after `register_graph_routes` and that `session/new` calls `CodingSessionAdmission.admit`. |
| `ARBORA-ACP-R001.6` | **Refusal.** `CodingSessionAdmission` refuses with typed reasons added to `AcpRefusalReason` (`arbora/acp/session_policy.py:21`). `untrusted_root` applies at `session/new`. `capability_not_declared` applies to a request outside the declared set. `permission_denied` applies when the client rejects `session/request_permission`. `client_disconnected` applies when no client is connected. Each refusal returns before any forwarded request. | `tests/acp/test_coding_session_refusal.py` asserts each reason arrives as the typed refusal, with no forwarded request. |
| `ARBORA-ACP-R001.7` | **Evidence.** Each admission and each forwarded capability request emits one trace record. Fields: session ID, principal ID, tenant, workspace root, capability name, permission outcome (`standing`, `granted`, `denied`) and refusal reason. The record carries no file content and no command output. It uses the existing emitter in `arbora/observability`. | `tests/acp/test_coding_session_evidence.py` asserts the record fields for an admit, a granted write and a denied command, and the absence of file content. |
| `ARBORA-ACP-R001.8` | **Hot-path proof.** The entry point is the ACP wire method `session/new` served by `arbora/acp/routes.py`. The test `tests/acp/test_coding_session_hot_path.py` opens a session with a temporary trusted root. The agent then requests `fs/read_text_file` and `fs/write_text_file`. The read passes and the write waits for `session/request_permission`. An untrusted root is refused at `session/new` with `untrusted_root`. | `tests/acp/test_coding_session_hot_path.py` runs against a fake connected client and the registered route, and asserts the three observations. |
| `ARBORA-ACP-R001.9` | **Serve bounded read and preview duplex sessions.** Register the authenticated JSON-RPC/SSE route in the shared gateway. Bind each transient connection to the existing verified caller and coding admission snapshot. Correlate bounded client responses, order events, cancel on disconnect, and refuse cross-caller reuse and replay. The local read/preview profile drives AU's received plan with client tools only. The central child retains native planning and server tools. Forward reads; preview writes and commands but return permission_required before any effect request. | Real isolated HTTP/SSE client tests read a temporary file, receive a diff and command preview in order, and prove no write or command dispatch. Missing authority, wrong caller, undeclared reads, stale or duplicate responses, disconnect and queue limits refuse. Durable approvals and effect execution remain owned by the original parent rows. |
| `ARBORA-ACP-R001.9.1` | **Project admitted AU runs through the ACP SDK.** Reuse the received RunRequest and AU native streaming observer, session policy and Pydantic coding presenter. Provide an explicitly composed stdio server without a second agent loop or history store. Bound transient sessions, prompts and all outgoing updates. Revalidate the caller after awaited admission. Resolve client paths lexically to absolute workspace paths; the client still owns filesystem containment. Permit declared reads and non-executing effect previews only. Owner cancellation and teardown remain possible after expiry. | Real SDK subprocess tests initialize, open sessions, stream text, read a temporary client file, cancel active model and read waits, and refuse path escapes, unsupported effects/recovery, identity changes and bounds. Scripted models and synthetic host authority are explicit. Installed-wheel, remote-auth and durable-history acceptance are separate. |
| `ARBORA-ACP-R001.9.2` | **Mount the authenticated experimental HTTP/SSE profile.** Register the shared ACP projection through the gateway's existing identity path. Bind every message to the original verified principal, tenant and scopes; never accept identity or credentials from a query string or JSON-RPC body. Bound frames, connections, queues and response correlation. Refuse duplicate IDs, stale responses and SSE replay. Cancel active AU work on disconnect. | Real HTTP/SSE tests use the SDK codec and temporary client workspace. Prove unauthorized and cross-caller refusal, ordered streaming, bounded backpressure, duplicate/stale response refusal and disconnect cancellation. This custom profile is not standardized Streamable HTTP or durable replay. |
| `ARBORA-ACP-R001.9.3` | **Governed central final answer.** An opt-in factory uses the existing authenticated `agents.run` operation, native task plan and server tools. Bind the actual admitted task/run receipt; publish only its committed final answer. Refuse continuation and nonterminal outcomes. Confirm cancellation through the task owner and readback, otherwise report uncertainty. Bearer renewal supplies the current caller only with unchanged verified authorization and verifier configuration. | Real SDK/HTTP tests cover final answer, private-event exclusion, nonterminal refusal, cancellation before and after admission, uncertain settlement and renewed credentials. Controlled model and owner ports are not live storage or installed-wheel proof. |
