# ARBORA-INGRESS requirements

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-INGRESS-R001` | **Public ingress rename with identity-provider and secret-store cutover (rollup).** Subsystem: deployment, public ingress. Entry: `setup-config` (`arbora/deployment/cli.py`) rendering a profile loaded by `load_environment_profile`. Arbora serves from its own hostname with a renamed TLS certificate, ingress resource and secret. The key lives in the secret store and arrives through an external-secret object. The identity provider redirect URIs are updated, and a time-bounded redirect from the prior hostname exists during cutover. Children: `.1` model, `.2` profile wiring, `.3` legacy redirect, `.4` served probe. Provisioning of the secret store and provider client runs from `services/`. Depends on: `ARBORA-IDENTITY-R024`. | Root journey: `tests/qualification/identity/test_cutover_probe.py::test_cutover_probe_signs_in_on_new_hostname` (L6) runs `scripts/identity_probe.py` against the new hostname and asserts MCP and REST answer under the renamed ingress. |
| `ARBORA-INGRESS-R001.1` | **Typed public-ingress profile model.** Subsystem: deployment, public ingress. Code: `arbora/deployment/public_ingress_identity.py::PublicIngressProfile` and `public_ingress_profile_from_mapping`, a closed-schema value object with `version` 1. Caller chain: `setup-config environments validate` → `arbora/deployment/cli.py::main` (line 127) → `_run_environments` (line 66) → `load_environment_profile` (`arbora/deployment/genesis_environments.py:813`) → `public_ingress_profile_from_mapping` (called once `ARBORA-INGRESS-R001.2` adds the call). Shape: `PublicIngressProfile` (frozen dataclass) and `PublicIngressProfileError` (subclass of `EnvironmentProfileError`) in `arbora/deployment/public_ingress_identity.py`; the private `_validate_*` helpers each check one key. Rule: the profile carries `public_origin`, `tls_secret_ref`, `callback_uri` and `trusted_proxy`. It refuses an unknown or missing key and a malformed TLS reference. It also refuses a callback outside the origin, a non-loopback HTTP origin and a wildcard Host or proxy. Refusals: `PublicIngressProfileError` naming the key. Errors never hold a secret value. Writes: none. Depends on: none. | Test: `tests/deployment/test_public_ingress_identity.py::test_valid_mapping_renders_deterministic_redacted_profile` (L1) proves the render. `tests/deployment/test_public_ingress_identity.py::test_refusal_never_leaks_secret_value` and `tests/deployment/test_public_ingress_identity.py::test_unknown_field_refuses` prove the refusals. |
| `ARBORA-INGRESS-R001.2` | **Profile wiring into environment rendering.** Subsystem: deployment, public ingress. Caller chain: `setup-config environments show` → `arbora/deployment/cli.py::main` (line 127) → `_run_environments` (line 66) → `load_environment_profile` (`arbora/deployment/genesis_environments.py:813`) → `profile_summary` (line 1068); `setup-config generate` → `_run_generate` (line 49) → `write_config` (`arbora/deployment/config_generator.py:478`). The browser boundary reads the origin at `arbora/identity/browser_composition.py:47` from `runtime_config.webui_origin` (`arbora/core/settings.py:275`). Shape: add field `public_ingress: PublicIngressProfile` to `EnvironmentProfile` (line 272) next to `NetworkInputs` (line 234, which already carries `ingress_host`); parse it in `load_environment_profile` with `public_ingress_profile_from_mapping`; extend `profile_summary` and `write_config`. Rule: the renderer emits the ingress host, TLS secret reference, callback URI and trusted proxy from the profile. It emits `identity.public_origin` into `~/.config/arbora/config.json`. WebAuthn origin, Origin verification and OIDC and SAML callbacks read that value. No domain or provider default exists. Refusals: `PublicIngressProfileError` naming the key. Writes: rendered configuration files only. Depends on: `ARBORA-INGRESS-R001.1`. | Test (planned, see test-spec.md): `tests/deployment/test_public_ingress_identity.py::test_profile_renders_origin_callback_and_proxy` (L3). It runs the CLI render and asserts the output values and the refusal for a missing key. |
| `ARBORA-INGRESS-R001.3` | **Time-bounded legacy hostname redirect.** Subsystem: deployment, public ingress. Caller chain: `setup-config environments show` → `arbora/deployment/cli.py::_run_environments` (line 66) → `profile_summary` (`arbora/deployment/genesis_environments.py:1068`) → the new redirect route output. Shape: add `legacy_hostname` and `legacy_redirect_until` to `PublicIngressProfile` in `arbora/deployment/public_ingress_identity.py` with a private `_validate_legacy_redirect` helper beside the other `_validate_*` helpers; `profile_summary` emits the route. Config in the profile: `legacy_hostname` and `legacy_redirect_until` (ISO date, at most 90 days after render). Rule: until that date the legacy host answers 308 to the same path on the new origin. After the date the render omits the route. A render with a date beyond 90 days refuses with `LEGACY_REDIRECT_TOO_LONG`. Writes: rendered files only. Depends on: `ARBORA-INGRESS-R001.2`. | Test (planned, see test-spec.md): `tests/deployment/test_public_ingress_identity.py::test_legacy_redirect_is_bounded` (L1). It asserts the 308 route, the omission after the date and the refusal. |
| `ARBORA-INGRESS-R001.4` | **Cutover served probe.** Subsystem: deployment, release qualification. Caller chain: release qualification runs `scripts/identity_probe.py` (new, owned by `ARBORA-IDENTITY-R024`) with `--base-url` set to the new origin → the browser helpers of `tests/qualification/browser/browser_login.mjs` → MCP and REST endpoints. Shape: this row adds no module; it adds one test module `tests/qualification/identity/test_cutover_probe.py` that calls the probe script with the cutover origin and asserts the two endpoint answers. Rule: the probe completes a browser sign-in through the identity provider. It then calls the MCP and REST endpoints under the renamed ingress. Output holds no cookie or credential. Depends on: `ARBORA-INGRESS-R001.2`, `ARBORA-IDENTITY-R024`. | Test (planned, see test-spec.md): `tests/qualification/identity/test_cutover_probe.py::test_cutover_probe_signs_in_on_new_hostname` (L6). It asserts sign-in success and both endpoint answers. |
