# ARBORA-HARNESS-PLUGINS requirements

Every requirement this specification owns, with the proof that closes it. The design is in [plan.md](plan.md). The test contract is in [test-spec.md](test-spec.md).

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-HARNESS-PLUGINS-R001` | **One harness-neutral bundle core is composed from the registry (rollup).** Arbora composes one `BundleSpec` from its registry and its installed content packages. One renderer per harness profile writes the files. Children `.1` to `.7` deliver it. | Children `.1` to `.7`. (planned) |
| `ARBORA-HARNESS-PLUGINS-R001.1` | **Model: the closed harness profile table.** The closed set is `claude-code`, `opencode`, `codex` and `grok`. Each profile names its manifest layout, its loopback OAuth callback, its hook kind (`mcp_tool` or `command`) and its event map. Each profile lists its supported parts: skills, commands, agents, hooks, MCP servers and status line. The table is the one source of these facts. Caller chain: `arbora/console.py:main` → `arbora/harness_plugins/cli.py::bundle_command` → `profiles.profile(name)`. Shape: new `arbora/harness_plugins/profiles.py` with frozen dataclass `HarnessProfile`, enum `HookKind` and the tuple `PROFILES`; no helper to reuse. | Test: `tests/harness_plugins/test_profiles.py::test_profile_table_is_closed_and_complete`. (planned) |
| `ARBORA-HARNESS-PLUGINS-R001.2` | **Core composer reads the registry and the content packages.** `compose_bundle(caller, profile)` returns a frozen `BundleSpec`. It holds one MCP entry for the arbora door with the public base URL from config. It holds the door skills of `US-CONTENT-R007` and the skills in the declared list `harness_plugins.skills`. It holds one agent definition per registered agent profile that the caller may run. Each agent definition delegates through `act` with `agents.run`. The bundle copies no MCP prompt; the harness lists the served prompts itself. Caller chain: `arbora/console.py:main` → `cli.py::bundle_command` → `compose.py::compose_bundle` → `arbora/api/ops/registry_factory.py::get_registry`. Shape: new `arbora/harness_plugins/compose.py` with `BundleSpec`, `SkillRef`, `AgentDef` and `HookIntent`; reuse the SDK content convention for skill folders. | Test: `tests/harness_plugins/test_compose.py::test_bundle_holds_door_skills_agents_and_no_prompt_copy`. (planned) |
| `ARBORA-HARNESS-PLUGINS-R001.3` | **Renderers write one deterministic tree per profile.** `render(spec, profile, out_dir)` writes the files of the profile layout only. It sorts every key and list. It returns the tree digest: SHA-256 over sorted relative paths and file bytes. Two runs on one registry must return one digest. The digest is the bundle version. Caller chain: `cli.py::bundle_command` → `render.py::render` → the renderer function of the profile. Shape: new `arbora/harness_plugins/render.py` with `render`, `tree_digest` and one function per profile; reuse `hashlib.sha256`. | Test: `tests/harness_plugins/test_render.py::test_two_renders_give_one_digest`. (planned) |
| `ARBORA-HARNESS-PLUGINS-R001.4` | **Command: arbora plugin bundle.** `arbora/console.py:main` dispatches `plugin` before server start, as it dispatches `identity reconcile`. `arbora plugin bundle --harness ID` writes to `--out DIR`. Without `--out`, it writes under `${XDG_CACHE_HOME}/arbora/plugins/<harness>/<digest>/`. `--print-path` prints only the absolute tree path on one line. Caller chain: `arbora` console script → `arbora/console.py:main` → `arbora/harness_plugins/cli.py::main` → `bundle_command`. Shape: new `arbora/harness_plugins/cli.py` with `argparse` sub-commands; reuse the dispatch form of `reconcile_command` in `arbora/identity/client_contract.py`. | Test: `tests/harness_plugins/test_cli.py::test_bundle_print_path_prints_one_absolute_line`. (planned) |
| `ARBORA-HARNESS-PLUGINS-R001.5` | **Refusal: typed reasons write no file.** The command refuses `HARNESS_UNKNOWN` for a name outside the table and `ENDPOINT_UNSET` when the public base URL is unset. A stale publication receipt refuses `reingestion-unreconciled` unchanged. Each refusal exits 2 and writes no file. Caller chain: `cli.py::bundle_command` → `gate_mcp_resource_publication` (`arbora/fleet/mcp_resource_reconciliation.py`) → `compose_bundle`. Shape: enum `BundleRefusal` in `arbora/harness_plugins/cli.py`; reuse `PublicationGateResult`. | Test: `tests/harness_plugins/test_cli.py::test_refusals_exit_two_and_write_nothing`. (planned) |
| `ARBORA-HARNESS-PLUGINS-R001.6` | **No secret and no file outside the tree.** A bundle file must hold no token, secret, password or client secret. Caller chain: `render.py::render` → `render.py::check_tree` before the digest. Shape: function `check_tree` in `arbora/harness_plugins/render.py`; reuse the secret patterns of the repository secrets gate. | Test: `tests/harness_plugins/test_render.py::test_bundle_holds_no_secret_and_no_escaping_path`.
