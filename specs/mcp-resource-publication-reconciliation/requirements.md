# ARBORA-MCP-RESOURCES requirements

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-MCP-RESOURCES-R001` | **Publication gate refuses without a valid receipt (rollup).** arbora's MCP resource/template publication path never claims a candidate generation is published unless a `ReconciliationReceipt` exists, matches that exact candidate, and is fresh; otherwise it returns the typed `reingestion-unreconciled` result. Delivered through its child requirement, producer first. | Covered by `ARBORA-MCP-RESOURCES-R001.1` plus `ARBORA-MCP-RESOURCES-R003` (not yet specified). |
| `ARBORA-MCP-RESOURCES-R001.1` | **Typed `ReconciliationReceipt` model and publication gate.** `arbora/fleet/mcp_resource_reconciliation.py` defines a frozen `ReconciliationReceipt` and `gate_mcp_resource_publication()` returning a typed `PublicationGateResult`: `"reconciled"` only for a receipt matching the exact tenant, `catalog_generation`, `snapshot_digest`, and all four families (`tools`, `prompts`, `resources`, `resource_templates`) within a freshness bound; `"reingestion-unreconciled"` with a stable `reason` (`missing`, `stale`, `invalid`) otherwise. Caller chain: `require_reconciled_for_swap` in `arbora/fleet/mcp_resource_reconciliation.py` → `gate_mcp_resource_publication(receipt, *, tenant_id, expected_generation, expected_digest, now_ms, max_age_ms)`; no catalog code calls either yet (child `ARBORA-MCP-RESOURCES-R003.2`). Shape: frozen `ReconciliationReceipt { tenant_id, catalog_generation, snapshot_digest, acknowledged_families, issued_at_ms }` and `PublicationGateResult { status, reason, receipt }` in `arbora/fleet/mcp_resource_reconciliation.py`. | Test: `tests/fleet/test_mcp_resource_reconciliation.py::test_valid_receipt_is_reconciled`. `tests/fleet/test_mcp_resource_reconciliation.py` covers missing, stale, digest-mismatched, generation-mismatched, partial-family, and wrong-tenant receipts all returning `reingestion-unreconciled`, and a fully matching fresh receipt returning `reconciled`.  |
| `ARBORA-MCP-RESOURCES-R002` | **medulla is the sole admissible receipt source.** The gate may only treat as reconciling a receipt medulla issued after durably committing the candidate's four-family projection. Arbora never synthesizes or locally fabricates a passing receipt. Producing contract: [`MEDULLA-REPO-INGEST-001`](https://github.com/Knuckles-Team/medulla/blob/main/specs/repository-index-and-ingestion/spec.md) (owned by medulla). Caller chain: `tests/fleet/test_mcp_resource_receipt_source.py` parses every module under `arbora/` and finds `ReconciliationReceipt(...)` constructed only in `arbora/fleet/mcp_resource_reconciliation.py`; the gate (`gate_mcp_resource_publication`) only evaluates a receipt it is handed, so a receipt reaches it from the engine through the publish step planned in `ARBORA-MCP-RESOURCES-R003.2`. Shape: the frozen `ReconciliationReceipt { tenant_id, catalog_generation, snapshot_digest, acknowledged_families, issued_at_ms }` in `arbora/fleet/mcp_resource_reconciliation.py`, with no issuer field and no second constructor in `arbora/`. | Test: `tests/fleet/test_mcp_resource_receipt_source.py::test_no_arbora_module_constructs_receipt_outside_gate_module`. Cross-repository link verification: this spec's `spec.md` cites the exact EG spec ID and URL. No arbora code path constructs a `ReconciliationReceipt` locally outside of test fixtures.   |
| `ARBORA-MCP-RESOURCES-R003` | **Gate wired at the one catalog-publish entry point (rollup).** Entry: the fleet catalog reload. Caller: `refresh_serving_catalog` (`arbora/fleet/onboarding.py:831`) → `FleetCatalogReader` publish step (`ARBORA-FLEET-R051`) → `require_reconciled_for_swap` (`arbora/fleet/mcp_resource_reconciliation.py:123`). Only an all-families `reconciled` result allows the swap of the active generation. The guard `.1` exists; `.2` wires it. Depends on: `ARBORA-FLEET-R051.1`, `ARBORA-FLEET-R051.2`. | Rollup. It passes when `ARBORA-MCP-RESOURCES-R003.1` and `ARBORA-MCP-RESOURCES-R003.2` pass. |
| `ARBORA-MCP-RESOURCES-R003.1` | **Swap guard function.** `arbora/fleet/mcp_resource_reconciliation.py` adds `require_reconciled_for_swap()`, which wraps `gate_mcp_resource_publication()` and raises a typed `PublicationRefusedError` carrying the `PublicationGateResult` for any `reingestion-unreconciled` result, and returns the receipt only for `reconciled`. The publish step can then call one function that cannot be bypassed by ignoring a return value. Caller chain: no catalog publish step calls it yet (child `ARBORA-MCP-RESOURCES-R003.2`); `require_reconciled_for_swap` in `arbora/fleet/mcp_resource_reconciliation.py` → `gate_mcp_resource_publication`, as `tests/fleet/test_mcp_resource_reconciliation.py` exercises. Shape: `require_reconciled_for_swap(receipt, *, tenant_id, expected_generation, expected_digest, now_ms, max_age_ms)` and `PublicationRefusedError(result: PublicationGateResult)` in `arbora/fleet/mcp_resource_reconciliation.py`. | Test: `tests/fleet/test_mcp_resource_reconciliation.py::test_swap_guard_raises_typed_refusal`. Unit tests: missing, stale, and invalid receipts raise `PublicationRefusedError` with the typed result attached and the stable `reason`. A matching fresh receipt returns the receipt.  |
| `ARBORA-MCP-RESOURCES-R003.2` | **Call the guard from the publish step.** Entry: the catalog reload. The publish step `FleetCatalogReader.publish_generation(candidate, receipt)` (added by `ARBORA-FLEET-R051.2`) calls `require_reconciled_for_swap` first. Only then does it swap the active generation. The four families are `tools`, `prompts`, `resources`, `resource_templates`. On `PublicationRefusedError` the last-known-good generation stays active and the reload outcome carries the typed result (`missing`, `stale` or `invalid`). The receipt comes only from the engine (`ARBORA-MCP-RESOURCES-R002`). The freshness bound is config key `mcp_resources.receipt_max_age_ms` in `~/.config/arbora/config.json`, default 300000, bounds [1000, 3600000], unit milliseconds. Depends on: `ARBORA-FLEET-R051.2`, `ARBORA-MCP-RESOURCES-R003.1`. Caller chain: catalog reload (`refresh_serving_catalog` in `arbora/fleet/onboarding.py`) → `FleetCatalogReader.publish_generation` (new, `arbora/fleet/catalog_reader.py`, added by `ARBORA-FLEET-R051.2`; the method does not exist yet) → `require_reconciled_for_swap` → generation swap. Shape: `publish_generation(candidate, receipt)` (new) on `FleetCatalogReader` in `arbora/fleet/catalog_reader.py`, reusing `require_reconciled_for_swap`. | Test: `tests/fleet/test_mcp_resource_reconciliation.py::test_publish_step_refuses_missing_stale_invalid_and_allows_match` (L3) drives `publish_generation` with each receipt.  |
| `ARBORA-MCP-RESOURCES-R004` | **Status docs are the gate's result, not hand-maintained prose.** `docs/status.md`'s "Explicitly unavailable surfaces" row and `docs/fleet.md`'s reconciliation paragraph describe exactly the `reingestion-unreconciled` result the gate returns. Caller chain: `tests/fleet/test_mcp_resource_status_docs.py` reads `GateStatus` from `arbora/fleet/mcp_resource_reconciliation.py` and checks `docs/status.md` and `docs/fleet.md` against it; the docs text is hand-written, not generated. Shape: the `docs/status.md` unavailable-surfaces row and the `docs/fleet.md` reconciliation paragraph, each using the literal result `reingestion-unreconciled`. | Test: `tests/fleet/test_mcp_resource_status_docs.py::test_docs_cite_gate_unreconciled_code`. A docs-consistency check (or review note) confirms the status/reason vocabulary in both docs matches `arbora/fleet/mcp_resource_reconciliation.py` exactly.  |
