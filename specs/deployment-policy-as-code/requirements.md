# ARBORA-DEPLOY-POLICY requirements

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-DEPLOY-POLICY-R001` | **Declarative deployment manifest and plan preview.** GraphOS declares a deployment as a versioned manifest. The manifest lists the component set. It covers engine shards, the gateway, connectors, and the optional web UI. Each component carries a digest-pinned image or revision. It carries an identity mode. It carries a secrets-backend reference. It carries capacity. Unknown fields are errors. Duplicate keys are errors. Misspelled intent is never silently ignored. `plan` computes a typed diff between the manifest and the live state. `plan` is read-only. | A manifest lint test fails an unknown key. It fails a floating (non-digest) image reference. A plan test asserts the diff is correct. It asserts no live mutation occurs. |
| `ARBORA-DEPLOY-POLICY-R002` | **Idempotent apply convergence.** `apply` converges the live state to the manifest. Convergence is idempotent. Create, update, and destroy are each idempotent. Re-running is always safe. Missing inputs fail closed. The failure names the gap. The engine never fabricates missing inputs. The apply receipt binds the manifest digest. It binds the per-component revisions. It binds the per-component outcome. | An apply test re-runs apply against an already-converged state. It observes zero changes with an identical receipt. A missing-input refusal test confirms the gap is named. It confirms nothing is created. |
| `ARBORA-DEPLOY-POLICY-R003` | **Drift inspection and destructive-change approval gates.** `plan` and `apply` surface drift between live state and the manifest. A destructive operation requires an explicit approval receipt. Destructive operations cover destroy, scaling below one, and data-losing operations. The approval reuses the existing two-person, time-bound elevation model. The receipt must exist before `apply` proceeds. Drift inspection itself is read-only. | A drift test detects a manually changed replica count in the live state. An approval test refuses a destructive apply without a receipt. It admits the same apply with a fresh receipt. It expires a stale receipt. |
| `ARBORA-DEPLOY-POLICY-R004` | **Declarative policy bundles as code.** A versioned policy bundle declares scoped rules. A rule names the principal group, the action, and the resource scope. Scopes are tenant, graph, tenant-graph, or cluster-wide. A compiler lowers rules into the existing RBAC/scope evaluator. Enforcement is server-side on every mutation. It runs through the one access boundary. MCP and REST share the same decision (existing non-negotiable). Grants and revocations authorize under the currently applied policy. They never authorize under the proposed one. One bundle binds a given scope at most. Binding a bundle is itself a governed operation. | A policy test compiles a bundle. It enforces the bundle on a served mutation. It confirms the MCP and REST paths reach the same decision. Scope-exclusivity refusal returns a typed error. Proposed-policy self-authorization returns a typed error. |
| `ARBORA-DEPLOY-POLICY-R005` | **Epistemic policy predicates (stated advantage).** A policy rule may carry an epistemic condition. The condition evaluates against record attributes. It reads the validity window, provenance confidence, and evidence count. It evaluates through the engine access service. A mutation lacking the required epistemic evidence refuses with a typed reason. Missing evidence never counts as a pass. Stated advantage: a declarative policy language over static subject and resource attributes cannot express epistemic conditions. GraphOS policy gates mutations on live epistemic state. | An epistemic-policy test admits a write backed by in-validity, high-confidence evidence. It refuses the identical write after the evidence expires. It refuses a write whose evidence refs are missing. |
| `ARBORA-DEPLOY-POLICY-R006` | **Served agent surface: llms.txt, MCP best-practice resources, versioned skill export.** The served deployment publishes an `llms.txt`. The file is a machine-readable documentation map. It generates from the deployed version. The deployment also publishes MCP best-practice resources. The product skill export is versioned. It carries a digest stamp against the release. The skill always matches the served version. Skill and resource generation fail closed on an unreconciled fleet state. The failure reuses the existing reconciliation-receipt gate (ARBORA-MCP-RESOURCES-R001). | A served-surface test asserts `llms.txt` matches the deployed digest. It asserts the MCP resources match. A refusal test confirms generation refuses a stale reconciliation receipt. It confirms generation refuses a missing receipt. |
