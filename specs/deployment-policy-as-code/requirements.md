# ARBORA-DEPLOY-POLICY requirements

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-DEPLOY-POLICY-R001` | **Declarative deployment manifest and plan preview.** Stage: deployment plan. Caller: registered op `deploy.manifest.plan` (effect read, scope `ops:read`) → `arbora/api/ops/deploy.py::handle_manifest_plan` → `arbora/deployment/manifest.py::plan_manifest`. Model `DeploymentManifest` in `manifest.py`: `schema_version`, `name`, `components[]`. A component has `id`, `kind`, `image`, `revision`, `identity_mode`, `secrets_ref` and `capacity{cpu_millis, memory_bytes, replicas}`. `kind` is `engine_shard`, `gateway`, `connector` or `webui`. `image` is a digest reference. `identity_mode` is `none`, `local` or `external`. `secrets_ref` is an `openbao://` or `env://` reference. The op reads the manifest by name from `~/.config/arbora/deploy/manifests/<name>.yaml`; the name matches `^[a-z0-9][a-z0-9_-]{0,63}$`. Parsing uses the strict loader of `arbora/deployment/image_digests.py`: unknown and duplicate keys are errors. Live state comes from the port `LiveStateReader`, backed by one read `fleet.call` named by `~/.config/arbora/deploy.yaml` key `tools.live_state.<target>`. `plan_manifest` returns `DeploymentDiff` entries `{component_id, change, from, to}`, sorted by id. Changes: `create`, `update`, `scale`, `destroy`. Refusals: `MANIFEST_INVALID`, `IMAGE_NOT_DIGEST_PINNED`, `LIVE_STATE_UNAVAILABLE`, `LIVE_STATE_TOOL_NOT_READ`. Writes: none. Depends on: ARBORA-DEPLOY-R017.18, ARBORA-DEPLOY-R017.19. | Test: `tests/api/test_deploy_manifest_served.py::test_plan_returns_typed_diff_and_makes_no_write_call` (L3, `invoke`). `tests/deployment/test_manifest.py::test_unknown_key_duplicate_key_and_floating_image_are_rejected` (L2). |
| `ARBORA-DEPLOY-POLICY-R002` | **Idempotent apply convergence.** Stage: deployment apply. Caller: registered op `deploy.manifest.apply` (effect admin, `confirm=PLAN`, scope `fleet:control`, idempotency `KEY_REQUIRED`) → `handle_manifest_apply` → `arbora/deployment/manifest.py::apply_manifest`. The function recomputes the diff and requires its digest to equal the confirmed `plan_digest`. For each `create` or `update` entry it asks placement (`ARBORA-DEPLOY-R017.1`, `R017.2`) and runs the confirmed steps (ARBORA-DEPLOY-R017.21). The receipt `ApplyReceipt{manifest_digest, components[{id, revision, outcome}], receipt_digest}` carries no timestamp. `receipt_digest` is the SHA-256 of the canonical JSON. A re-run on a converged state has an empty diff, makes zero calls and returns the same receipt. A missing input refuses `MANIFEST_INPUT_MISSING` naming the gap, before any call. Arbora fabricates no input. Writes: governed `fleet.call` effects keyed `deploy:<manifest_digest>:<component>:<node>`. Depends on: `ARBORA-DEPLOY-POLICY-R001`, ARBORA-DEPLOY-R017.21. | Test: `tests/api/test_deploy_manifest_served.py::test_second_apply_makes_zero_calls_and_returns_identical_receipt` (L3). `::test_missing_input_names_the_gap_and_creates_nothing` (L3). |
| `ARBORA-DEPLOY-POLICY-R003` | **Drift inspection and destructive-change approval.** Stage: deployment plan and apply. Caller: `deploy.manifest.plan` returns `drift[]` for entries with change `update` or `scale`. It returns `destructive[]` for `destroy`, `scale` below one replica, and any component whose persistent volume is removed. `deploy.manifest.apply` requires the param `approval_elevation_id` when `destructive[]` is not empty. Arbora reads the elevation through the access service (`arbora/access/service.py`). It requires status `approved`, `remaining_ms > 0`, and justification equal to `deploy-destructive:<destructive_digest>`. The two-person rule is the elevation service rule: the approver differs from the requester. Refusals: `APPROVAL_REQUIRED`, `APPROVAL_EXPIRED`, `APPROVAL_MISMATCH`. Drift inspection is read-only. Depends on: `ARBORA-DEPLOY-POLICY-R001`, `ARBORA-DEPLOY-POLICY-R002`, `ARBORA-IDENTITY-R001`. | Test: `tests/api/test_deploy_manifest_served.py::test_manual_replica_change_is_reported_as_drift` (L3). `::test_destructive_apply_needs_a_fresh_approval_and_a_stale_one_expires` (L3). |
| `ARBORA-DEPLOY-POLICY-R004` | **Declarative policy bundles as code.** Stage: policy administration. Caller: registered ops `policy.bundle.validate` (read) and `policy.bundle.bind` (effect admin, `confirm=CONSOLE`, scope `fleet:control`) in `arbora/api/ops/policy.py`. They call the engine methods `ValidatePolicyBundle` and `BindPolicyBundle` (EG-IDENTITY-R702) through the caller's engine client. Arbora parses the bundle file `~/.config/arbora/policy/<name>.yaml` with the strict loader and sends it unchanged. The engine compiles it into its isolation layer and enforces it in the one access boundary. MCP and HTTP share one decision because both call the same op. Engine refusals `POLICY_SCOPE_BOUND` and `POLICY_SELF_AUTHORIZATION` pass through unchanged. Arbora holds no rule table and no evaluator. Writes: engine only. Depends on: EG-IDENTITY-R702, `ARBORA-OPS-R009`. | Test: `tests/api/test_policy_bundle_served.py::test_bound_bundle_denies_a_mutation_on_http_and_mcp_with_the_same_decision` (L3, loopback engine). `::test_scope_exclusivity_and_self_authorization_refusals_pass_through` (L3). |
| `ARBORA-DEPLOY-POLICY-R005` | **Epistemic policy predicates.** Stage: policy enforcement. Caller: any registered write op (for example `ingest.submissions.create`) → invoke pipeline → engine mutation → engine access service (EG-IDENTITY-R703). Arbora adds no predicate code. The pipeline returns the engine refusals `POLICY_EVIDENCE_MISSING`, `POLICY_EVIDENCE_EXPIRED` and `POLICY_CONFIDENCE_LOW` as typed refusals with the engine reason. Missing evidence is never a pass. Depends on: EG-IDENTITY-R703, `ARBORA-DEPLOY-POLICY-R004`. | Test: `tests/api/test_policy_epistemic_served.py::test_write_with_valid_evidence_admits_and_expired_or_missing_evidence_refuses` (L3, loopback engine). |
| `ARBORA-DEPLOY-POLICY-R006` | **Served agent surface: llms.txt, best-practice resources, versioned skill export.** Stage: serving. Caller: HTTP `GET /llms.txt` (a `ProtocolRoute` in `arbora/api/http/protocol_routes.py`, owner `arbora.fleet`) → `arbora/fleet/agent_surface.py::build_llms_txt`. The file lists the served operations and docs links of the deployed version and its release digest. MCP best-practice resources register through the FastMCP bridge from the same module. The skill export command `arbora skills export --digest-stamp` writes the skills with the release digest in each header. Every artifact calls `gate_mcp_resource_publication` (`arbora/fleet/mcp_resource_reconciliation.py`) first. A stale or missing receipt refuses `reingestion-unreconciled` and publishes nothing. Depends on: `ARBORA-MCP-RESOURCES-R001`. | Test: `tests/fleet/test_agent_surface_served.py::test_llms_txt_and_resources_match_the_deployed_digest` (L3, HTTP and MCP). `::test_stale_or_missing_receipt_refuses_generation` (L3). |
| `ARBORA-DEPLOY-POLICY-R007` | **Rollout records a deployment through deployment.record.** After each successful rollout, the deploy executor must call the served operation `deployment.record`. The call carries the release artifact digest, the target and the time. Caller: the deploy operation entry in the policy-as-code deploy path. A failed record refuses with `UNAVAILABLE` and marks the rollout unrecorded. Depends on: `ARBORA-OPS-R853.1`. | Test: a served deploy test asserts one `deployment.record` call per rollout and none on a failed rollout. |
