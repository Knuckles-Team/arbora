# ARBORA-MESSAGING requirements

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-MESSAGING-R001` | **Typed channel supervision state machine.** Arbora models each supervised messaging backend's lifecycle as a closed, typed state enum (`STOPPED`, `STARTING`, `RUNNING`, `BACKING_OFF`, `DEGRADED`, `STOPPING`) with a fixed legal-transition table; `InboundRouter` reports this state per backend. Delivered as the rollup of `ARBORA-MESSAGING-R001.1` (typed model, transition table, refusal tests) plus the router wiring that reports it live. | Unit tests over the typed model prove every legal transition and refuse every illegal one; an integration test confirms `InboundRouter` reports the live state per registered backend. |
| `ARBORA-MESSAGING-R001.1` | **Typed state model, transition table, and refusal tests.** Arbora defines the `ChannelSupervisionState` enum and a `TRANSITIONS: dict[ChannelSupervisionState, frozenset[ChannelSupervisionState]]` table as the sole authority for legal moves, plus a `transition(current, target)` function that returns the target on a legal move and raises a typed `IllegalSupervisionTransition` otherwise. No router wiring is required for this slice. | Unit tests cover every legal transition pair and assert a representative set of illegal pairs (including `STOPPED -> RUNNING` and `DEGRADED -> RUNNING`) each raise `IllegalSupervisionTransition` with the attempted pair in its message. |
| `ARBORA-MESSAGING-R002` | **Health-gated start.** `InboundRouter.start()` transitions a registered backend through `STARTING` and only reaches `RUNNING` once `backend.is_connected` is observed true; a backend that is not connected at start is recorded `STOPPED` (skipped), never `RUNNING`. | A unit test with a fixture backend whose `is_connected` is `False` asserts the router records it as not running and does not create a listener task for it; a connected fixture backend reaches `RUNNING`. |
| `ARBORA-MESSAGING-R003` | **Bounded restart backoff with healthy-run reset.** On a recoverable listener failure, `_supervise_backend` moves the backend to `BACKING_OFF`, computing its next delay from `MESSAGING_LISTEN_BACKOFF_BASE_S` (floored at a nonzero value so a zero base never busy-loops), doubling on each consecutive failure, capped at `MESSAGING_LISTEN_BACKOFF_MAX_S` (default 60s); a run lasting at least `MESSAGING_LISTEN_HEALTHY_RESET_S` (default 60s) resets the delay to base before the next failure. | A unit test drives a sequence of simulated short-lived failures and asserts the delay sequence is monotonically bounded by the cap; a separate test simulates one long-lived healthy run followed by a failure and asserts the delay resets to base. |
| `ARBORA-MESSAGING-R004` | **Graceful stop and drain.** `InboundRouter.stop()` moves every supervised backend to `STOPPING` before cancelling its listener and inbox-reaper tasks, awaits their completion with `return_exceptions=True`, then reports `STOPPED`; a task observing `asyncio.CancelledError` during a backoff wait propagates as clean shutdown and triggers no further restart attempt. | A unit test cancels a router with an in-flight backoff wait and asserts no restart task is scheduled after `stop()` returns and that the task collection is empty. |
| `ARBORA-MESSAGING-R005` | **Typed degraded adapter state and configuration-aware health.** Arbora records configured adapter failures as DEGRADED with typed reasons. It continues creating other configured channels. R005.1 defines configuration-aware health and alert eligibility. | Named registry and health cases in R005.1 exercise these behaviors. |
| `ARBORA-MESSAGING-R005.1` | **Typed adapter degradation and configuration-aware health.** Preserve the configured missing/import-failed adapter record as DEGRADED with AdapterMissing or AdapterImportFailed. Continue creating other configured channels. Expose components.messaging_intake on authenticated GET /api/dashboard/health and graph_configure(action="health"). Return stable enabled, configured, state, alert_eligible, and backends fields. Set enabled only when MESSAGING_INTAKE_ENABLED is explicitly true and the process is the served network host or KG_DAEMON_ROLE=host (ARBORA-MESSAGING-R007). Credentials alone never enable intake. Set configured when at least one supported backend has credential material. Never return credential values. Set state to disabled when intake is off. Use not_configured when enabled but no backend is configured. Use degraded when enabled with any unavailable configured backend. Use healthy only when every configured backend is connected. Set alert_eligible true exactly when enabled and state is not_configured or degraded. Build backends in stable ID order from configured backend IDs and typed degraded-record IDs. Each row has id, configured, state, and nullable reason_code. States are not_configured, disabled, connected, or unavailable. Use not_configured without credentials and disabled when intake is off. Use connected only when enabled and is_connected=true. Otherwise mark configured rows unavailable. Map AdapterMissing to adapter_missing, AdapterImportFailed to adapter_import_failed, and false is_connected to backend_not_connected. Never expose credentials or raw exception text. Alert evaluators may emit only when alert_eligible=true. Health reads never send messages. Keep unauthenticated /health and /health/ready detail-free. | MSG-T07 and MSG-T09–MSG-T12 prove typed failure preservation, state distinctions, alert eligibility, matching authenticated projections, safe output, and detail-free probes. |
| `ARBORA-MESSAGING-R006` | **Supervision/adapter ownership boundary.** Arbora's supervision types import only `agent_utilities.messaging.base.MessagingBackend`'s public adapter contract and `agent_utilities.messaging.models`. Arbora implements no channel adapter and agent-utilities implements no supervision, health gating, or backoff. This requirement links `AU-INTEGRATION-001` (`AU-INTEGRATION-R002`, `AU-INTEGRATION-R019`) as the agent-utilities-owned messaging/router spec this boundary depends on. | A source-level import check confirms `arbora/messaging/{router,registry,service}.py` import no agent-utilities module outside `agent_utilities.messaging.{base,models}` and `agent_utilities.core.config`. |
| `ARBORA-MESSAGING-R007` | **Served channel gateway.** The served network host (the `streamable-http` deployment container) is the channel gateway. With `MESSAGING_INTAKE_ENABLED` explicitly true (the string `false` is false), it enters Telegram and Mattermost intake. `KG_DAEMON_ROLE=host` keeps the same right. The engine WorkItem lease of `ARBORA-MESSAGING-R800.1000` still admits one poller for each channel identity. Credentials alone never start intake. Arbora admits an inbound message only when `MESSAGING_ALLOWED_SENDERS` lists its `<platform>:<user id>` sender. An empty list admits no sender. An unlisted sender gets no turn, no command reply and no elicitation delivery. Arbora runs an admitted message as one turn under its process session. The action policy and fleet admission apply as normal. | `tests/messaging/test_alert_operation.py::test_the_served_network_host_owns_intake_only_on_an_explicit_true`, `test_only_listed_senders_are_admitted` and `test_an_unlisted_sender_gets_no_turn_and_no_reply`. |
| `ARBORA-MESSAGING-R008` | **Alert intake operation.** `messaging.alert` is served at `POST /api/v1/messaging/alert` through the invoke pipeline. It needs a bearer, the `kg:write` scope and an `Idempotency-Key`. It accepts `{"text"}` and the `msg`, `message` and `content` aliases, and an Alertmanager webhook body, and refuses an alert with no text. It delivers to `MESSAGING_DEFAULT_PLATFORM` and `MESSAGING_DEFAULT_CHANNEL`. Telegram and other adapter channels go through the governed messaging send under the caller's session. Mattermost goes through `fleet.call` admission to the mattermost connector (`MESSAGING_MATTERMOST_FLEET_SERVER` and `MESSAGING_MATTERMOST_FLEET_TOOL`), so Arbora makes no Mattermost API call. The EG effect journal holds each send at most once per key. A missing destination, a refused send or a connector error is a typed refusal, never a delivery. `TELEGRAM_API_BASE_URL` selects a self-hosted Bot API server. | `tests/messaging/test_alert_operation.py` and `tests/test_real_boot_messaging.py::test_an_admitted_alert_reaches_the_telegram_double`, which boots Arbora against a faked Bot API. |
| `ARBORA-MESSAGING-R800` | **Messaging adapter contract, command registry and the full channel adapter set (rollup).** `arbora.messaging` owns the `MessagingBackend` contract and the capability and event models. It owns the single built-in command registry and the Telegram markdown renderer. It owns seventeen channel adapters, each behind its own install extra. The chat adapters are telegram, mattermost, discord, slack, whatsapp, teams, googlechat and googlemeet. The others are matrix, irc, signal, imessage, line, twitch, synology, voicecall and nextcloud. Children `.1` through `.6` cover model, behavior, wiring, refusal, evidence and hot-path proof. | See each child. |
| `ARBORA-MESSAGING-R800.1` | **Model.** `MessagingBackend`, `MessagingConfig`, `InboundEvent`, `Message`, `SendResult` and the capability declarations are the public records; adapters register through the `agent_utilities.messaging` entry-point group. | `tests/messaging/test_primitives.py::test_command_specs_match_registry_and_filter_by_surface` |
| `ARBORA-MESSAGING-R800.2` | **Behavior.** One command registry serves every platform and the terminal. Built-in commands answer locally. Plain text and model-routed or agent-routed commands go to the agent. | `tests/messaging/test_primitives.py::test_builtin_commands_answer_locally` |
| `ARBORA-MESSAGING-R800.3` | **Wiring.** Adapters load lazily so importing `arbora.messaging` pulls in no platform SDK; a missing SDK reports its extra by name. | `tests/messaging/test_channel_adapters.py` binds the entry-point group and lazy loading. |
| `ARBORA-MESSAGING-R800.4` | **Refusal.** An unknown command or botname-suffixed command never raises; a command outside the surface is hidden from that surface's listing. | `tests/messaging/test_primitives.py::test_non_builtin_text_falls_through_to_the_agent` |
| `ARBORA-MESSAGING-R800.5` | **Evidence.** Tests assert the registry views per surface, built-in replies and the Telegram rendering contract with no network. | `tests/messaging/test_primitives.py::test_render_structure_leaks_no_markdown_markers` |
| `ARBORA-MESSAGING-R800.6` | **Hot-path proof.** The proof renders and dispatches ten thousand mixed messages and records p50 and p99 latency per call. | `tests/messaging/test_primitives.py::test_render_inline_forms` |
| `ARBORA-MESSAGING-R700` | **Action notification and webhook dispatch.** `arbora/messaging/action_dispatch.py` delivers the notifications and webhooks of a completed ontology Action from the engine's action outbox event. `NotificationSpec` and `WebhookSpec` are closed Pydantic models. A `Notifier` sink delivers or journals; a webhook goes through an injected HTTP transport or is recorded. Every dispatch returns an outcome record with `delivered`, `transport` and a timestamp from an injected clock. A raising sink or failing transport yields a recorded error and never blocks the Action. `dispatch_action_notification` in `arbora/messaging/service.py` delivers notifications through governed reach. Dispatch is O(1) per spec and holds no shared state, so concurrent dispatches run in parallel. Budget: p50 under 0.1 ms and p99 under 1 ms excluding transport, memory under 1 MiB. Engine side: `EG-UNIFIED-DATA-PLANE-R700`. | `tests/messaging/test_action_dispatch.py` asserts recorded, error, delivered, non-2xx and exception outcomes and that no outcome raises. |
| `ARBORA-MESSAGING-R800.1000` | **Intake lease on the engine WorkItem methods.** One durable WorkItem per `(platform, identity)` admits one inbound poller. Arbora calls the engine's served `submit`, `get`, `claim`, `renew` and `defer` methods and keeps no lease state of its own. | `tests/messaging/test_lease.py` |
| `ARBORA-MESSAGING-R800.1001` | **Behavior.** Two contenders for the same platform get one owner. A lost renewal stops that platform only, and intake stops when no platform holds a lease. The renewal thread keeps the caller's context. A stopped intake defers its lease so another owner can claim it. | `tests/messaging/test_lease.py::test_two_contenders_cannot_both_own_intake` |
| `ARBORA-MESSAGING-R800.1002` | **Refusal.** Intake opens no poller when the engine serves no WorkItem methods. It opens none for a session without a tenant or for a row with another identity. | `tests/messaging/test_lease.py::test_missing_authority_opens_no_poller` |
