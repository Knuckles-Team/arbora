# ARBORA-HOST requirements

| ID | Requirement | Verification |
|---|---|---|
| `ARBORA-HOST-R001` | **Cross-repository composition boundary assignment.** Arbora composes its runtime gateway on top of boundary contracts in which the graph engine owns ontology, SHACL and durable graph records, the connector SDK owns connector transport, and the agent runtime exposes only its public agent control-plane API; the web UI consumes this composed boundary rather than any internal package. | An import-boundary census confirms each dependency is reached only through its published public API, enforced as a continuous-integration check. |
| `ARBORA-HOST-R001.1` | **Arbora owns the MCP, REST and API serving code that agent-utilities 3.0.0 drops.** The agent runtime keeps only the harness. Arbora holds the served MCP backing surface in `arbora/mcp_server/backing/` (graph tools, server factory, tasks extension, intent contract, remote OAuth broker, client credentials). It holds the control-plane contracts and the single session port in `arbora/api/contracts/`. It holds WebUI contact and voice delegation in `arbora/webui_host/`. Arbora imports no agent runtime `mcp`, `gateway`, `server` or `api` module and requires `agent-utilities>=3.0.0,<4.0.0`. Child slice of `ARBORA-HOST-R001`. | `tests/test_package_layout.py::test_arbora_imports_no_au_serving_packages` finds no such import under `arbora/`. |
| `ARBORA-HOST-R001.2` | **Arbora registers the harness host bindings at startup.** The `arbora` MCP entry point registers three bindings with `agent_utilities.host_ports`. The native toolset provider serves its operations through the governed `_execute_tool` path. The fleet catalog provider maps each server to its public prefix and URL from the served multiplexer. The session keepalive factory renews the session. Shutdown clears the bindings. Without them the harness fails closed. Child slice of `ARBORA-HOST-R001`. | `tests/mcp_server/test_harness_host.py` proves fail-closed before registration, bound tools, fleet and keepalive after it, and cleared bindings after shutdown. |
| `ARBORA-HOST-R001.2.1` | **Arbora binds the run-loop providers at startup.** `bind_run_ports()` registers a run decision provider, a model provider and a run event sink with `agent_utilities.host_ports`. The engine serves no run-plan decision, so the decision provider returns the harness default plan over the Arbora model registry. The model provider builds a chat-completions-compatible model for a registry endpoint. The event sink writes each run event to the engine as a `RunEvent` node. `AgentRunPort` adapts the harness `AgentRunExecutor` to the Arbora agent execution port. A run without a model fails closed. Child slice of `ARBORA-HOST-R001.2`. | `tests/test_agent_runs.py` runs an agent through `AgentRunPort` with a fake model and checks the persisted run events. It also checks the registry model and the fail-closed run. |
| `ARBORA-HOST-R001.2.2` | **A served agents.run call runs end to end.** The invoke pipeline admits the call and dispatches it to the A2A service. The A2A WorkItem authority admits one engine WorkItem through `arbora.work_items` and leases it. The harness `AgentRunExecutor` runs the agent, and the authority commits the outcome to the WorkItem. The run events reach the engine as `RunEvent` nodes. The idempotency key derives the task id, so the A2A authority owns replay for `agents.run`. Every `InvokeServices` that registers `agents.run` declares that owner. The served `arbora` factory runs an A2A `message/send` the same way. Child slice of `ARBORA-HOST-R001.2`. | `tests/test_agents_run_end_to_end.py` invokes `agents.run` with a fake model and a fake engine client. It also boots the served factory and posts `message/send` to `/a2a`. Each test checks the completed task, the committed outcome and the persisted run events. |
| `ARBORA-HOST-R001.2.3` | **The served process mounts the operation-invoke API.** When `GRAPH_SERVICE_ENDPOINTS` names an engine, `mcp_server()` mints the process authority first and composes one `HostedInvocation`. The composition joins the generated registry and the bootstrap client factories over one engine client pool. It adds the control-lease plan store, the policy gate and a schema validator over the engine contract schemas. The web UI host calls `POST /api/v1/ops/<op_id>` on that API. `fleet.call` refuses until the served root composes the governed fleet operations. Child slice of `ARBORA-HOST-R001.2`. | `tests/test_served_operation_api.py` mounts the composed API the way the web UI co-service does. It calls `agents.run`, `query.uql` and `eg.graph.GetNodesByLabel` over HTTP and checks each value the web UI parses, including the `memory.*` operations. It also lists the served MCP intent verbs and runs `find`. |
| `ARBORA-HOST-R001.2.4` | **Tool-call RunEvents are queryable provenance.** Each `tool_call` RunEvent stores the governed verb (`tool_name`), the operation (`op`), and for `fleet.call` the connector `server` and `tool`, plus `ok`, as node properties. A UQL property filter then answers which connector tool a run used, without parsing the payload string. Proving test: `tests/mcp_server/test_arbora_016_served_fixes.py::test_tool_call_run_events_carry_queryable_tool_provenance`. |
