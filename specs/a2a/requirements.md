# GRAPHOS-A2A requirements

| ID | Requirement | Verification |
|---|---|---|
| `GRAPHOS-A2A-R001` | **A2A facade over the engine and agent services.** graph-os implements A2A as a facade over the public graph-engine and agent-utilities services exposed through MCP and REST, starting with unary agent-card discovery and task send/get/list/cancel, then adding durable task streaming and resubscribe without a second task store. Split into `GRAPHOS-A2A-R001.1` (the resubscribe method-table slice) with the event-cursor-backed streaming fixture remaining open under the parent. | Proven by contract tests covering the unary task operations and a durable stream/resubscribe fixture. |
| `GRAPHOS-A2A-R001.1` | **Fail-closed `tasks/resubscribe` stub on the A2A method table.** graph-os registers `tasks/resubscribe` in the A2A JSON-RPC method table with typed, validated params, and refuses it with a distinct error until durable, restart-safe event-cursor-backed streaming exists — never silently succeeding, never reported as an unrecognized method. | Proven by a test asserting `tasks/resubscribe` validates params and is refused with a dedicated JSON-RPC error code distinct from "method not found". |
| `GRAPHOS-A2A-R002` | **Inbound task routing with caller-filtered tool exposure.** graph-os routes inbound A2A tasks through the existing agent orchestration port into engine-backed work items. Caller-filtered assembly selects the agent and its exposed tool subset. The caller sees only authorized tools. `GRAPHOS-A2A-R002.1` covers fail-closed refusal when assembly selects a tool subset. `GRAPHOS-A2A-R002.2` covers caller-filtered enforcement through the AU signed dispatch carrier. That child remains open under the parent. | Proven by integration tests asserting routed tasks map to durable work-item identities and exposed tool subsets match the caller's authorization. |
| `GRAPHOS-A2A-R002.1` | **Fail-closed refusal when assembly selects a tool subset.** graph-os refuses `dispatch()` with a distinct error before durable admission when a routing decision selects a tool subset. The signed AU dispatch carrier cannot enforce an allowlist at execution time. | Proven by a test asserting dispatch raises `A2AAssemblyUnavailable` whenever `decision.selected_tools` is non-empty. |
| `GRAPHOS-A2A-R002.2` | **Caller-filtered tool-subset enforcement at dispatch.** The signed AU agent-dispatch carrier accepts and enforces an allowed-tool subset end to end. The caller's exposed tools match its authorization at execution time. Split into `GRAPHOS-A2A-R002.2.1` (the owner-named AU dependency) because graph-os has no public door to add this itself. | Proven by integration tests asserting an enforced tool subset at execution, not just an advisory list. |
| `GRAPHOS-A2A-R002.2.1` | **Owner-blocked: AU carried, enforced tool-subset field.** `agent_utilities.orchestration.agent_dispatch.AgentTurnEnvelope`/`enqueue_agent_turn` has no field or mechanism to carry and enforce a caller-filtered tool allowlist at execution time. graph-os's `WorkItemA2AAuthority._enqueue`/`dispatch` (`graph_os/a2a/authority.py`) already refuse every request carrying `decision.selected_tools` (`GRAPHOS-A2A-R002.1`) rather than pass through an unenforced allowlist. agent-utilities owns adding that carried, enforced field. Until an agent-utilities spec exists and lands it, `GRAPHOS-A2A-R002.2` cannot be implemented in this repository. | No graph-os-side test is possible against the current AU carrier contract. Verified by the fail-closed tests bound to `GRAPHOS-A2A-R002.1` continuing to refuse rather than silently drop the filter. Tracked as the explicit cross-repo dependency recorded in `tasks.md`. |
| `GRAPHOS-A2A-R003` | **No duplicate skill or prompt harvesting in the multiplexer.** graph-os removes the multiplexer's separate skill and prompt harvesting path so there is exactly one owner for tool, skill, and prompt discovery, with no duplicate ingestion path remaining in the running package. | Proven by a runtime absence check confirming no duplicate harvest path is present or reachable in the deployed package. |
| `GRAPHOS-A2A-R004` | **Served MCP bridge runs FastMCP 4, matching its declared version.** graph-os's deployed MCP bridge runs on FastMCP 4 end to end, including native WebMCP and a single composition loop, so the dependency version it declares matches the version actually serving requests. | Proven by semantic tests run against the exact declared FastMCP and engine dependency versions, and a live-deployment probe confirming the served version. |
| `GRAPHOS-A2A-R005` | **Durable, fail-closed A2A approval exchange for tool calls.** graph-os defines a human approval exchange for pending tool-call effects in the A2A contract. The task enters an input-required state. The effect requires a signed approval message bound to that specific pending call. Approval stays disabled until the full signed exchange is implemented and proven end to end. Until then, every approval attempt is rejected. Split into `GRAPHOS-A2A-R005.1` (the fail-closed `graphos.plan/confirm` stub) with `GRAPHOS-A2A-R005.2` (the full signed chain) remaining open under the parent. | Negative tests prove approval is refused while unimplemented. A later full-chain test covers request, signed approval and execution. |
| `GRAPHOS-A2A-R005.1` | **Fail-closed `graphos.plan/confirm` stub on the A2A method table.** graph-os registers `graphos.plan/confirm` in the A2A JSON-RPC method table with typed, validated params, and refuses every confirmation attempt with a distinct error until the full signed human approval exchange exists. | Proven by a test asserting `graphos.plan/confirm` validates params and is refused with a dedicated JSON-RPC error code distinct from "method not found". |
| `GRAPHOS-A2A-R005.2` | **Full signed human approval chain and input-required task emission.** A pending effect moves its durable task to `input-required` with a typed, server-attested pending-call envelope, and an atomic compare-and-set consumes a revocable human grant exactly once before the effect runs. Split into `GRAPHOS-A2A-R005.2.1` (the durable, revocable human-grant store with atomic compare-and-set consumption) with the rest of the chain (input-required task emission wired to a live pending call, signature verification, and the full request-to-execution test) remaining open under this row. | Proven by a full chain test from request through signed approval to execution, and negative tests for replay, changed params, different human, and expired/revoked grant. |
| `GRAPHOS-A2A-R005.2.1` | **Durable, revocable human-grant store with atomic compare-and-set consumption.** No grant store exists anywhere in graph-os today (confirmed by source search: no `GrantStore`/compare-and-set human-approval primitive is defined). `GRAPHOS-A2A-R005.2` cannot move a task to `input-required` and consume a grant exactly once until this store — issuance, lookup, and a single atomic consume-once operation keyed by pending-call id — is specified and built as its own component. | Proven by unit tests asserting a grant is consumed at most once under concurrent compare-and-set attempts, and that consuming an expired or revoked grant fails closed. |
